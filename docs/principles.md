# 阅读与协作原则

本页是 Nozeli 产品交互与材料交接的既定原则；具体能力是否已实现见[当前状态](status.md)。

## 人的位置

人是研究材料的读者、作者和共同思考者，不是系统的调度员或审批队列。Nozeli 首先是独立的阅读与编辑工具：即使不配置任何 AI，也能阅读、批注、编辑受支持的文件。Agent 承担常规执行与内容工作；程序负责保存文件、身份、版本、任务投递和冲突事实，不让模型用格式化文字模拟数据库，也不让用户替系统搬运上下文。

## 材料交接

- **打开不等于发送**：打开文件不启动模型。只有显式发送时，程序才冻结来源项目、文件身份、当时内容或未保存缓冲、版本摘要、选段或批注、可读前后文及所属对话，一并交给 Agent。模型收到的是真实可读的材料，而不是路径或需要它自行重造的内部字段。
- **锚点忠实于所见**：文本锚点使用原文范围与引文，PDF 使用页内选段与坐标，图片区域截图是视觉证据、不冒充精确结构锚点。文件变化导致锚点漂移时显示原引用与变化说明，不悄悄套用到新内容上。
- **切换不丢现场**：切换文件或项目前分别保存草稿与阅读位置；A 项目未发送的问题不会被带进 B 项目。晚到的回复写入发起时的讨论，不抢占当前阅读位置、选区或输入。
- **自动保存不等于交接**：已发送材料不随后续编辑自动更新；续聊或重新发送时按当前内容重新冻结。

## 修改与归属

- 每次修改的作者、时间与版本由程序从真实操作来源记录；模型不自行填写归属，未知外部修改不冒认给 Agent。
- 人的未保存编辑、并发冲突与可回退结果始终保留，不静默覆盖。
- 后台 Work 的候选修改冻结在独立工作区，由人审核差异后显式**接受**（合入项目）或**丢弃**（不合入）；接受处理方案不等于自动接受最终成果，保存审核意见也不派工。
- 用户说“修改”即为该请求的意图，不再强加统一的“计划→确认→执行”流程；需要选择时才澄清。
- 取消、重连与结果应用都按已接受请求的身份处理，不重复执行、不把旧答复当本轮结果。原会话无法恢复时，明确告知是新会话接手，并提供已保存的对话、材料与交接摘要。

## 后台与前台

- 前台快速响应与分流，后台 Worker 各自推进整块任务；后台推进不使前台失去可用性，人不守进度条。
- 敏感或管理员执行经同项目待办由用户明确授权；待办同意与操作系统认证是两件事，提权仅由真实 OS 认证完成。
- 同会话输入串行接收与排队；不相关任务可并行，同文件写入由程序协调。
