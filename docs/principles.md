# 阅读与协作原则

本页是 Nozeli 产品交互与材料交接的既定原则；具体能力是否已实现见[当前状态](status.md)。

## 人的位置

人是研究材料的读者、作者和共同思考者，不是系统的调度员或审批队列。Nozeli 首先是独立的阅读与编辑工具：即使不配置任何 AI，也能阅读、批注、编辑受支持的文件。Agent 承担常规执行与内容工作；程序负责保存文件、身份、版本、任务投递和冲突事实，不让模型用格式化文字模拟数据库，也不让用户替系统搬运上下文。

## 材料交接

- **打开不等于发送**：打开文件不启动模型。只有显式发送时，程序才冻结来源项目、文件身份、当时内容或未保存缓冲、版本摘要、选段或批注、可读前后文及所属对话，一并交给 Agent。模型收到的是真实可读的材料，而不是路径或需要它自行重造的内部字段。
- **锚点忠实于所见**：文本锚点使用原文范围与引文，PDF 使用页内选段与坐标，图片区域截图是视觉证据、不冒充精确结构锚点。文件变化导致锚点漂移时显示原引用与变化说明，不悄悄套用到新内容上。
- **切换不丢现场**：切换文件或项目前分别保存草稿与阅读位置；A 项目未发送的问题不会被带进 B 项目。晚到的回复写入发起时的讨论，不抢占当前阅读位置、选区或输入。
- **自动保存不等于交接**：已发送材料不随后续编辑自动更新；续聊或重新发送时按当前内容重新冻结。

## 修改与归属

- 每次修改的作者、时间与版本由程序从真实操作来源记录；模型不自行填写归属，未知外部修改不冒认给 Agent。
- 人的未保存编辑、并发冲突与可回退结果始终保留，不静默覆盖。
- 后台 Work 的候选修改冻结在独立工作区，由人审核差异后显式**接受**（合入项目）或**丢弃**（不合入）；接受处理方案不等于自动接受最终成果，保存审核意见也不派工。
- 用户说“修改”即为该请求的意图，不再强加统一的“计划→确认→执行”流程；需要选择时才澄清。
- 取消、重连与结果应用都按已接受请求的身份处理，不重复执行、不把旧答复当本轮结果。原会话无法恢复时，明确告知是新会话接手，并提供已保存的对话、材料与交接摘要。

## 后台与前台

- 前台快速响应与分流，后台 Worker 各自推进整块任务；后台推进不使前台失去可用性，人不守进度条。
- 敏感或管理员执行经同项目待办由用户明确授权；待办同意与操作系统认证是两件事，提权仅由真实 OS 认证完成。
- 同会话输入串行接收与排队；不相关任务可并行，同文件写入由程序协调。

## 自动维修与普通执行权限

- 普通 Agent 使用当前操作系统用户的文件、命令和网络能力，不按 frontdesk／orchestrator／worker 角色再增加普通路径授权。读取文件、工作区输入捕获、成果交付和合入分别判定；`.ccb` 等项目内目录不能仅因名称而成为读取禁区，也不能因无关受管元数据进入 Git 跟踪而阻断整个 Worker。Nozeli 自身数据库／Git 元数据不作为普通文档写入或合入对象；真实路径身份、草稿、并发变更与系统管理员认证仍保留。
- 技术故障先由宿主分类、保留真实状态和本地回执。启动、发布或技术收尾仅在宿主提供可核验、不会重放未知效果的恢复能力时执行有界程序恢复；provider 拒绝、鉴权、限流、网络错误及无恢复能力的缺陷不默认触发 Orchestrator／maintenance／backstage 模型诊断。用户明确请求诊断时才沿原范围交付必要证据，不把故障通知或诊断回复自动加入后续业务上下文。已明确声明的普通交付文件即使被 Git 忽略也须冻结，不静默省略、不直接覆盖原件。
- 日志持久化记录故障指纹、失败阶段、版本／平台、原任务关联、尝试及验证回执；重复事件去重计数，日志不包含凭据或用户全文、不自动上传。只有观察到恢复效果才解决，不以模型文字宣告修好。
- 自动恢复仅重试能证明未执行的输入准备、已冻结的发布或不重放模型的技术步骤；已开始或结果未知的命令不自动重放。原 Work／线程／候选／未发送草稿及用户接受决定保持；维修事件不另占业务 Work 名额、不派发替代任务。
- 无法由当前恢复能力修正的缺陷保留日志并标记待版本修复；不自动让模型反复核对同一故障，不热改已安装程序、篡改数据库或关闭保护伪造成功。需要修改源代码时采用正常源码候选与隔离验证；安装、重启、提权、删除用户数据和新增业务范围继续遵循当轮授权。真正需要人的冲突、权限或未知副作用决定仍须准确说明并提供真实操作。

## 默认 YOLO 与用户待办边界

- 三角色默认信任当前操作系统用户：普通命令、网络、文档读取、跨项目与未登记目录访问不产生授权请求，不要求用户先登记目标目录。文件身份、草稿和并发保护不是权限申请，不得用“权限不足”掩盖普通程序失败。原生 OMP 保持 yolo；这不是恶意代码沙箱，也不能保证拦住任意组合命令的危险效果。
- 用户待办只呈现成果审核与高危授权。高危指系统提权、破坏性大范围删除／格式化、不可逆破坏或向外泄露敏感数据等具体效果，而非按路径、角色或工具名称一概审批；审批必须准确说明对象、效果和风险。用户明确拒绝或撤销仍有约束力，程序不绕过。
- 澄清、普通问题和真实业务交接由 Orchestrator 在原范围内处理，不伪装成授权。连接／存储／交付故障、恢复和收尾按宿主分类与可核验能力处理，不因技术错误默认新增用户答题待办或模型工作。信息不足先用已有材料和可逆默认方案推进；无法可靠继续时保留进展和可见的中性状态，不能编造答案、静默丢弃问题或冒充已完成。需要人的实际业务取舍通过阶段成果审核表达；打开或阅读不构成接受，后台处理不构成授权。

## 退出与工作区恢复

- 正常退出按同一个有监督的请求完成涂鸦保留、页面保存确认、在途写入结算与进程收尾。等待超时只说明尚未确认，不能丢弃原请求；选择继续等待后，仍按原请求／页面代次核验晚到结果，不重复发送业务或跳过保存。
- 真实保存或清理失败应保留工作区并给出失败阶段与原始原因，让人返回检查；不能把已失败的操作描述为仍在等待，不能靠延长超时、吞掉异常或自动强退伪造成功。
- 恢复对话框由主进程提供明确的强制退出入口，二次确认且默认取消。确认后不再依赖失效页面、保存回执或正常收尾承诺；说明全部窗口、仅存内存的输入与运行任务风险。已持久化记录保留，不把强退写成任务完成，不自动重放中断输入。
- 退出只处理当前应用实例及可证明归属的子进程，不按名称或进程组清理其他程序；各平台分别验证，不能以 Linux 通过推定跨平台子进程清理通过。

## 项目重置为新项目

- 项目右键提供“重置为新项目”，须明确确认；它不是仅清理视图，也不删除实际文件或 Git。全局账号、API 源与模型默认项保持。
- 先完成该项目的保存／草稿保留、运行任务与终端停稳及在途写入结算，再将完整旧项目元数据与本机实例状态归档。未保存输入留在旧恢复记录中，不静默变成新项目输入。保存、进程退出或目录身份无法确认时拒绝重置，不以强制清空绕过。
- 同一实际目录生成新的项目与本机实例身份并重新加载；新项目不继承旧批注、会话、任务、草稿或布局。旧数据与归档位置保留可追溯，不重放旧输入／未知效果；失败只报告已确认的阶段，不自动重复归档或新建。
