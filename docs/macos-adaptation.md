> 源码基线：`5b0ebe8bb5d00e4f4e0b639a9cbda0bc6331e78d`，版本 `0.1.0-alpha.2`。
> 修订日期：2026-10-30。本文是实施前方案，依据源码静态核对；尚未完成 macOS 构建、运行或安装验收。
> 文中源码路径均相对于本仓库。后续以本仓库源码、锁文件和实际验收记录为准。
> 后续实施结果见 [macOS 实施记录](macos-implementation.md)；本页保留实施前方案与原验收门槛。

## 1. 结论与交付范围

macOS 是产品目标平台，见[路线与验收边界](roadmap.md)。现有 Electron、前端编辑器和部分 darwin 分支提供了适配基础，但不能据此认定整个产品已经兼容。主要未知项是安全文件操作、进程身份与回收、跨实例项目恢复，以及最终应用包内的原生运行时。

先完成关键原型，再确定完整实现与工期。原方案“完全可行”“两周 MVP”“3–5 周完整验收”不再作为交付承诺。

本方案使用以下统一口径：

| 交付层级 | 必须具备 | 不代表什么 |
|---|---|---|
| 开发验证版 | 在开发环境中完成阅读、批注、编辑与确定性协作验证 | 不代表普通用户可安装，不算 MVP |
| macOS MVP | 首期 darwin-arm64；可本地安装的 `.app` + dmg；下表规定的离线阅读/批注/编辑；基础受管 Agent 的发送、报告、审核、接受、停止与正常重启；合成夹具回归、安装包及指定版本间回退验收 | 不声明 Intel、universal、显式隔离、公证或公开分发资格；特殊项目恢复未验收时保持不可用 |
| macOS 完整平台验收 | 在明确的 macOS 版本与架构上完成路线要求的原生对话框、文件、权限、进程退出、分屏/独立窗口及恢复场景 | 不自动覆盖其他 macOS 版本、Windows、Intel 或第三方发行许可 |

普通用户阅读、批注、编辑不得依赖源码构建或模型服务。真实模型效果另列验收证据，需用户授权；确定性测试通过不能冒充真实模型验收。

普通受管执行默认使用当前用户身份，不自动启用 bubblewrap。macOS 首期显式隔离保持不可用；用户明确要求隔离时应拒绝该次隔离执行，不能静默转为普通执行。该范围不阻塞普通协作路径，但不构成沙箱保护承诺。

### MVP 文件格式与操作清单

以下是 macOS MVP 的必测范围，沿用[当前产品能力与限制](status.md)，不是已通过记录，也不增加新的格式能力。每行须使用合成文件，从最终安装包完成验证；开发阶段可复用已有测试，但不能以文本 smoke 替代其他格式。

| 格式 | MVP 必测操作 | 保存与重开检查 | 不包含的能力 |
|---|---|---|---|
| 纯文本、Markdown、代码、TeX/BibTeX 源文件 | 阅读、选区备注、文本编辑、撤销/重做；Markdown 预览、代码编辑器基本交互 | 保存后内容一致，冷重启可重开；中文、换行及未保存编辑提示正确 | TeX 编译、语言服务另列可选工具验收，不阻塞源码阅读编辑 |
| PDF | 阅读、大纲、搜索、缩放；文本选区及页/区域备注 | 备注重开后仍关联原版本、页和位置；仅阅读或备注不改写 PDF 原件 | 任意 PDF 内容编辑、将批注无损写回原件 |
| 图片（PNG/JPEG/WebP） | 阅读、缩放、区域备注 | 重开后区域与原图对应；仅阅读或备注不改写图像原件 | 像素编辑和图像格式转换 |
| DOCX | 阅读、正文段落及表格文本编辑、现有批注与作者标记 | 保存后重新解析并重开，核对文本、表格、批注锚点及夹具中的既有格式 | 任意 Office 特性的完整保真、正文段落和表格之外的批注保证 |
| XLSX | 阅读、现有单元格内容编辑与保存 | 重开后核对单元格内容；夹具包含图表或未知 OOXML 部分时，检查其仍保留在包中 | 图表显示、格式和结构编辑 |
| PPTX | 内嵌编辑、独立草稿保存、导出副本 | 冷重启恢复草稿；导出副本可重开，原件摘要不变；核对夹具中的文字与布局 | 旧 `.ppt`；图片、转场、母版的完整保真 |

共同验收要求：仅打开不得产生内容改写；保存本地备注不得启动 Agent；备注和对话保持原版本归属。对支持保存的格式，验证外部修改、权限拒绝和保存失败时原文件与本地编辑被保留，并给出明确反馈；对草稿/导出路径验证目标冲突不静默覆盖。已有格式限制须在验收记录中列明，不能把新发生的数据丢失归为“保真有限”。

每个必测操作记录夹具、操作步骤、预期结果、实际结果与证据。以上任一必测项失败、跳过或未执行，M3 均不能通过；若决定缩小范围，须先明确修订本表及用户可见能力声明，不能靠删测试默认缩减。

## 2. 已确认的源码事实

| 模块 | 源码事实 | 适配边界 |
|---|---|---|
| UI 与文档引擎 | Electron + React，集成 PDF.js、Monaco、SuperDoc、PPTist 等 | 可复用前端实现；输入法、快捷键、字体、剪贴板、格式保真和原生文件交互仍需真机验收 |
| Git / 终端 | 使用 dugite `3.2.3`、node-pty `^1.1.0`，安装后重建 node-pty | 必须验证目标架构产物、Electron ABI、执行权限和包内可重定位性 |
| OMP 构建 | `integrations/omp/prepare-private-runtime.mjs` 和 `build-private-runtime.mjs` 均拒绝非 linux-x64 | 两个入口都要适配，不能只解除准备脚本的限制 |
| OMP 锁定输入 | `private-runtime.lock.json` 明确固定 linux-x64 原生包、两个 `.node` 文件及各自哈希 | 目标平台原生输入是确定缺项；按平台/架构扩展锁定和校验 |
| 文件打开与发布 | `file-stream.mjs`、`execution-workspace.mjs`、`worktree-dependencies.mjs` 使用固定目录 fd 下的 procfs 路径 | 涉及打开、读取、校验、枚举、创建、重命名和清理，不只是路径替换 |
| 文件名等价与冲突 | `safeRelativePath` 的目录排除集、资源清单路径去重均按原始字符串比较；当前校验接受 `.GIT/config`、`.NOZELI/state.json`，也允许资源 `assets/A` 与 `assets/a` 同时声明 | macOS 目标卷可能把不同字符串解析为同一对象；需适配保留目录别名与目标冲突，不能只迁移 fd 操作 |
| Git 对象捕获 | `git-service.mjs` 将父进程 `/proc/<pid>/fd/<fd>` 传给 Git | 子进程读取方式需替换，摘要与 `SOURCE_CHANGED` 检查必须保留 |
| 进程身份 | `process-ownership.mjs` 的 stamp 是 `boot_id:启动时间ticks`，并非 `UUID:pid` | 防止重启和 PID 复用误判的语义必须保留 |
| 孤儿回收 | 还读取进程组、状态、argv、环境变量，并在操作前后复核身份 | 单独提供环境变量读取函数不能完成适配 |
| 特殊项目恢复 | `project-recovery-owner.mjs` 检查其他实例实际打开的 catalog.sqlite 句柄及 inode | 与 Agent 环境变量识别是不同问题，需独立设计 |
| 已有 darwin 分支 | 提权机制标记 `implemented-untested`；TeX 路径和部分助手启动参数有 darwin 处理 | 已有实现不是已验收能力；提权结果目录的直接路径方案也需复核竞争条件 |
| 应用启动 | `main.cjs` 的 `setDesktopName` 已有 Linux 守卫，`open-file` 已有监听；Ozone headless 在 `HIDDEN` 条件下设置 | 修改实际缺失的守卫，并验证已有事件路由；不是所有启动都默认 headless |
| 打包 | `package-portable.mjs` 是外层入口，`local-release.mjs` 执行装配和验证，二者使用 Linux 布局 | 同时适配装配、验证、元数据与最终包测试 |
| 测试 | 部分关键用例在非 Linux 平台跳过；integration 的 bwrap preflight 已有平台守卫，live 仍有 bwrap 检查 | 逐组调整，不以跳过安全用例换取绿色结果 |

本表是当前已识别清单，不宣称覆盖所有 Linux 假设。实施前按调用链继续检索 `/proc`、平台判断、外部命令和包内路径。

## 3. 实施阶段与决策门槛

### 阶段 0：干净环境摸底

在 macOS Apple Silicon 开发机上记录系统版本、架构、文件系统特性、Node/npm、Electron 内置 Node、Xcode CLT 和 Bun 版本。Bun 对齐 `private-runtime.lock.json`；外部 Node 先对齐 `.github/workflows/ci.yml`，再验证兼容性。

从仓库根目录进入 `apps/desktop`，使用锁定依赖与完整的前端构建顺序：

```sh
cd apps/desktop
npm ci --no-audit --no-fund
npm run build:pptist
npm run build:renderer
npm run test:unit
npm run start
```

逐条运行、记录结果，前置步骤失败时先排查。`postinstall` 会重建 node-pty；`build:pptist` 获取并校验锁定的上游源码，生成未纳入 Git 的 `vendor/pptist/dist`，这是 renderer 构建的前置条件。构建失败不得改用旧本机产物。上面的命令是未来实施步骤，本次文档修订未执行。

开发模式人工检查合成项目的阅读、批注、Markdown/代码编辑与保存。记录通过、失败、跳过和未执行项。缺少 OMP 时只评估可独立工作的阅读编辑能力，不推断 Agent 可用。

**产出**：环境清单、实际失败清单、基础交互记录，以及逐项对应 MVP 格式清单的测试计划。M0 的 Markdown/代码检查只是起点，不代表其他格式通过。普通用户最终安装仍不得需要这些开发工具。

### 阶段 1：私有 OMP 的目标平台构建

1. 同时调整 `prepare-private-runtime.mjs` 与 `build-private-runtime.mjs`；先支持 darwin-arm64，其他架构单独验收。
2. 为目标平台确定原生输入的精确包版本、文件、哈希和允许的未跟踪文件；扩展 lock 结构并保留 Linux 校验。缺失或不匹配时直接失败。
3. 审查全部锁定补丁和构建脚本中的 Linux 假设；补丁变更同步更新哈希与来源证明。
4. 用锁定 Bun 构建并生成目标平台 `runtime.json`。现有 `resolveBundledOmpRuntime` 已验证平台、架构、能力、来源和文件摘要，应保留这些约束。
5. 验证二进制实际启动及本地脚本化响应链路，而不只检查 manifest 能解析。目标平台产物不能覆盖后被误用于另一平台打包。

**决策门槛**：锁定输入可取得、完整构建可重现、产物可启动且能力校验通过。任何一项不满足，保留证据并重估范围，不能承诺协作 MVP 的日期。

### 阶段 2：安全文件操作与 Git 捕获

Node 标准 `fs` 没有本方案所需的 `fs.openat` API；不能把升级 Electron 当作解决方案。推荐先验证原生桥接模块路线，确定是否采用 N-API，再定接口和工期。原生模块必须纳入目标架构构建、依赖锁定、Electron/测试宿主加载、打包和签名验证。

接口应表达“在已打开目录中操作某个子项”，不要强迫所有平台返回可拼接的路径字符串。初步操作清单如下，最终以调用点盘点为准：

| 操作 | 必须保留的行为 | 主要消费方 |
|---|---|---|
| 相对打开与逐级遍历 | 固定每层父目录；不跟随符号链接；拒绝不安全类型 | `file-stream.mjs`、`execution-workspace.mjs` |
| fd 与目录项身份检查 | dev/ino、类型、链接数及纳秒时间等现有比较语义；读取后复查祖先和目录项 | `withSafeFile`、依赖复制 |
| 相对创建与目录枚举 | 独占创建、冲突保留、枚举时正确持有和释放目录句柄 | `documentParent`、依赖暂存 |
| 相对重命名与删除 | 保留原子发布、目标冲突、清理归属和回滚约束；覆盖 `renameat`/`unlinkat` 等所需能力 | 文档写入、依赖发布和暂存清理 |
| 子进程文件读取 | 有界 fd 数量、明确所有权和关闭时机；保持大文件流式处理 | `git-service.mjs`、`git-runtime.mjs` |

不能把目录子路径访问机械替换为 `/dev/fd/N/name`，也不能改回普通绝对路径而丢失目录固定与竞争检查。提权结果目录已有 darwin 分支须按同一安全目标审查；并入公共实现前验证其权限边界。

文件名等价规则必须与安全文件原语一起设计。APFS 有大小写敏感和不敏感的变体，并存在 Unicode 规范等价规则；不同路径字符串可能指向同一目录项。固定目录句柄、`O_NOFOLLOW` 和单个文件的身份检查不能独自防止保留目录别名绕过或多个写入目标互相重叠。

- 按实际目标卷验证文件名查找与等价规则，不仅按 `process.platform` 判断，也不能把统一转小写或 Unicode 规范化当作完整的文件系统等价判定。项目、执行副本、依赖源与发布目标所在卷分别核验；无法可靠判断时拒绝相关修改并说明原因。
- 对 `.git`、`.nozeli`、`node_modules` 等受限目录，别名与原名必须遵守相同访问限制；覆盖逐级路径校验、资源声明、读取、写入和清理调用点。保留用户文件名，不静默改名以绕过冲突。
- 在 Git 树落盘、依赖复制、人工审核应用及候选接受前，检查整组目标路径是否能在目标卷上唯一表示，包含目录段别名、文件与目录冲突。无法安全表示的集合必须在该批次写入前拒绝，保留原文件、候选与恢复材料；现存对象还须结合目录项和文件身份核验。
- 仅大小写重命名需要明确的操作与恢复规则，验证目标占用、未保存编辑关联和中断后的恢复，不能当成两个互不相关的删除与新建。跨卷复制按目标卷重新判定，不能沿用源卷的去重结果。

Git 捕获单独做原型，比较两条路线：

- 显式继承 fd 给 Git，并验证 `/dev/fd/N` 在目标系统和打包 Git 下的实际读取行为、偏移与生命周期；同时调整启动封装。
- 从已固定的文件句柄流式传给 `git hash-object --stdin`，评估逐文件调用的开销；不能为减少进程数退回整文件内存缓存。

两条路线都必须保留前后身份检查及 Git 对象摘要一致性检查。原型通过后再选定，不预先宣称 fd 继承必然等价。

**决策门槛**：实际覆盖读取、写入、依赖 provision、原子发布、清理、恢复与回滚；合成用例涵盖大文件、符号链接/硬链接、祖先目录交换、读取期间变化、目标并发出现和中断恢复。

文件名等价回归属于同一门槛：在大小写敏感和不敏感的 APFS 测试卷上，覆盖受限目录大小写变体、Unicode NFC/NFD 等价名称、同一目标的不同拼写、仅大小写重命名，以及源卷可区分但目标卷冲突的跨卷复制。验证冲突在写入前被拒绝、用户编辑和候选保持完整。无法执行的卷组合标为未验收；默认大小写不敏感 APFS 的必测项不能跳过后宣称 MVP 通过。

### 阶段 3：进程身份、回收与审计

抽象完整的进程查询能力，而非只有 `readProcessEnviron(pid)`：

- 区分同一 PID 的不同进程实例，包含可靠的启动身份和启动会话信息；保留跨重启、PID 复用和僵尸进程处理语义。
- 枚举同 uid 进程，读取进程组、父子关系、状态、精确 argv 和环境条目；区分“已退出”“读取被拒绝”“扫描不完整”。
- 回收前后重新核验进程身份，处理组长先退出、后代仍存活和扫描期间进程变化。
- 明确持久化 stamp 的格式、平台标识及历史记录兼容规则；不能把旧 stamp 按新格式误判为有效。

darwin 的系统进程接口、`sysctl` 的 `KERN_PROCARGS2` 等可作为原型候选，具体可用性、权限和数据完整性须在目标系统验证。`ps -E` 的展示文本会合并参数与环境条目的分隔信息，不作为精确身份核验依据；同 uid 也不预设所有信息必然可读。

改造 `process-ownership.mjs`、`omp-process-ownership.mjs`、`runtime-audit.mjs` 及其调用方。查询失败时保留资源并报告未核验；审计不完整不能返回“零进程”来代表已清理。环境变量只是归属证据之一，不能独自授权终止进程。

**决策门槛**：合成进程验证正常停止、强制终止、组长退出、孤儿后代、PID 身份变化、跨启动记录、权限不足和部分扫描失败。记录哪些后代被确认回收，不只检查父进程退出。

### 阶段 3B：特殊项目恢复的独立设计

`assertRecoverySourceStopped` 当前查找其他实例实际打开的登记数据库，读取项目记录，并复核句柄指向的 inode 与进程身份。源码明确指出 Electron 会改写初始环境，不能根据缺失环境变量推测默认配置目录。

该路径不能通过读取环境变量或直接移除 `RECOVERY_OWNER_UNVERIFIED` 限制来适配。先比较：

1. 原生进程/文件句柄查询是否能提供足够可靠的实例与数据库身份；只有路径列表不等于已固定数据库对象。
2. 应用层实例登记、持有锁或实例间协议是否能提供等价互斥证据；需要覆盖崩溃、陈旧记录、其他配置目录和旧版本实例，不能只要求新版本互相配合。

在设计和回归完成前，保留 macOS 特殊项目恢复不可用及原状态保留行为。MVP 可以明确排除此能力，但不能因此宣称完成路线中的全部恢复场景；正常重启与特殊项目恢复分别验收。

**决策门槛**：另一实例仍使用同一项目时必须阻止恢复；未知状态必须拒绝。验证数据库路径被替换/删除、不同配置目录、并发恢复、实例崩溃与重新启动等场景。

### 阶段 4：隔离能力声明

首期保持普通执行与显式隔离分开。UI 和错误信息明确 macOS 显式隔离不可用；测试同时覆盖普通路径可用和显式请求被拒绝。

测试入口按能力分组：普通协作不能因缺少 bwrap 被整体拦住；Linux 隔离回归继续保留。不能仅删掉 preflight 后让仍调用 bwrap 的测试运行失败，也不能把整组安全测试跳过后记为通过。

macOS 隔离机制属于后续独立调研，不预定 Seatbelt 与 Linux namespace 等价，也不把 Electron App Sandbox 或 Endpoint Security 当作现成替代。另行定义文件、网络、子进程与权限边界后再选型。

### 阶段 5：系统集成

1. 核对 `main.cjs`、`tools/start.mjs`、助手启动与测试入口的 Ozone 参数，只在适用平台设置；macOS GUI 测试使用经过验证的图形会话。
2. 验证已有 `open-file` 监听在冷启动、已有窗口、多个文件与应用恢复时的路由；将 `--nozeli-document`、`--nozeli-handoff` 等内部助手参数与系统打开事件分别测试。
3. 定义 `.app` 的 Info.plist、应用标识、显示名称、图标、菜单和文件关联；复用已有 darwin 菜单处理。
4. 为 `system-terminal-launch.mjs` 设计 Terminal.app 及可选终端的附着路径，验证 Finder 启动时的 PATH、引号、中文/空格路径、取消、退出和重连。Linux 终端参数只能作为参考。
5. 真机核对文件对话框、权限拒绝、输入法、快捷键、通知、分屏与独立窗口、未保存编辑提示和关闭恢复。
6. 提权能力单独验证系统授权、取消及结果核验；未通过时保持不可用，不把 `implemented-untested` 改写为已支持。

**产出**：按功能记录目标 macOS 版本和架构上的结果，不外推到整个 macOS 平台。

### 阶段 6：应用装配、签名与最终包验收

同时覆盖 `tools/package-portable.mjs` 和 `tools/local-release.mjs` 中的 `packageRelease`、`validateRelease`，以及它们的调用方。若引入打包库，先说明其解决的具体问题并锁定版本；不能只新增 dmg 外壳而沿用 Linux 装配路径。

目标布局包括 `Nozeli.app/Contents/MacOS`、`Contents/Resources/app`、Electron Helper/Frameworks、Info.plist 和图标。若选择 asar，须显式设计可执行文件与原生模块的包外路径，并验证所有运行时定位；不能默认路径不受影响。

打包流水线须定义：

1. 目标架构和最低系统版本；应用、Helper、OMP、Git、node-pty 及新增原生模块的架构和动态依赖检查。
2. 从锁定输入构建并装配；验证无开发目录、旧运行时或外部绝对路径依赖，保留许可证与来源元数据。
3. 嵌套可执行文件/模块签名、生成最终摘要、外层应用签名的顺序。OMP 现有 manifest 校验可执行文件哈希；签名若改变二进制，必须在其最终签名后生成摘要，再签外层应用，避免安装后完整性校验失败。
4. 生成 dmg、版本信息与 SHA-256；构建和验证阶段都识别 macOS 布局。
5. 从最终 dmg 安装到新的测试位置，使用独立合成配置，从 Finder 冷启动并验证；不是只在装配目录或开发终端中运行。

本地 MVP 可以采用经过验证的 ad-hoc 签名方式，但它不等于 Developer ID 或公证，也不能保证所有机器都能通过“右键打开”。按目标系统记录实际 Gatekeeper 行为；正式签名与公证另列前置条件和验收。

**最终包门槛**：无源码目录、开发 Node/npm/Bun 和系统 OMP/Git 依赖时，MVP 格式清单内的操作及内置运行时仍可工作；检查原生模块加载、脚本化协作、正常退出、冷启动、移动安装位置，并完成下述指定版本间回退验收。TeX、语言服务等可选外部工具分别声明。

本地 alpha 不免除第三方交付要求；在仓库既定公开分发审计完成前，不能因生成 dmg 就宣称可对外发行。提交、安装、发布仍遵循实施当轮授权。

### 阶段 6B：升级与数据回退

“保留旧版本”必须同时说明应用包和用户数据的处理。回退只承诺验收记录中明确列出的 macOS 版本对 A → B → A，不承诺任意降级，也不覆盖跨平台数据迁移。记录两个版本的提交、安装包摘要、系统/架构，以及应用配置、登记数据库、项目 `.nozeli`、会话/草稿和进程记录的兼容结论；不能仅按应用版本号推断数据兼容。

首个 macOS 包尚无已发布的 macOS 前版时，可选两个可安装、已完成基础验证的 macOS 候选包演练，并明确标为候选间验证；Linux 包不能充当 A。没有可用 A 时，该项标为未执行，M3 的回退门槛仍未完成。

1. **切换前停止写入**：先保存或明确保留编辑现场，正常退出相关实例，核实 Agent 与相关写入进程已停止，再生成一致性备份。不能在数据库仍写入时直接复制单个 SQLite 文件冒充完整备份；无法确认安全停止时中止切换并保留当前版本。
2. **备份覆盖完整数据**：盘点应用配置与登记数据库、各项目 `.nozeli`、批注/版本/会话/候选/草稿及项目原文件；记录备份位置、摘要与恢复对应关系。项目外的数据不能因备份了 `.app` 或用户配置目录而遗漏。备份保留原权限和敏感配置保护，不进入 Git 或 CI 公共产物。
3. **兼容时原地回退**：仅对已验证 A 可读取并继续写入 B 数据的版本对允许原地回退。替换完整、已核验的 A 应用包，不拼接两版运行时。验证回退后能打开项目、读取历史、继续保存，且旧批注与对话未被重新归属。
4. **不兼容或未知时恢复副本**：不得让 A 直接打开 B 的现用数据；回退流程须在启动 A 前完成隔离。保留 B 包及其完整数据，将升级前备份恢复到独立位置供 A 使用，按产品登记流程处理项目身份与配置。B 期间新增的编辑和会话继续保留在 B 数据中，不静默覆盖或丢弃；不承诺自动反向迁移。若恢复依赖尚未开放的特殊项目恢复能力，此路线不能算已通过。
5. **失败可保留现场**：备份失败、空间不足、升级或恢复中断时，不删除唯一可用的数据和应用包。记录当前可继续使用的版本与数据位置，以及重试/恢复方式；禁止以清空配置作为回退步骤。

**验收门槛**：使用包含原文件、批注、版本历史、会话、候选和草稿的合成项目完成 A → B → A。B 中实际产生新的保存和会话记录，再按兼容结论验证原地回退或备份恢复；检查数据可读、可继续编辑及 B 新增材料仍可找回。同时覆盖进程未停、备份失败、切换中断和兼容性未知时的拒绝路径。记录恢复耗时、恢复点和不能自动合并的数据，不把“旧应用能启动”作为数据回退通过。

### 阶段 7：测试、CI 与证据

| 验证层 | 已有入口/材料 | macOS 必须补齐 |
|---|---|---|
| 基础确定性测试 | `test:unit`、`test:integration` | 检查 preflight、平台守卫和实际执行用例；保留 Linux 回归 |
| 文件安全与恢复 | `core-file-stream.test.mjs`、`execution-workspace-dependencies.test.mjs` | 适配后启用当前非 Linux 被跳过的相关用例，补齐目录交换、发布、清理与回滚；不能只跑 `test:managed` |
| 文件名等价与跨卷冲突 | 路径校验、资源清单、Git 落盘与审核应用调用链 | 增加阶段 2 所列 APFS 合成回归；记录源卷和目标卷特性，验证受限目录别名、Unicode 等价、仅大小写重命名及冲突发生时零写入 |
| 进程生命周期 | `process-ownership.mjs`、`omp-process-ownership.mjs` 的行为契约 | 增加合成进程用例；`test:provider-terminal` 不能代替身份与后代回收测试 |
| 特殊项目恢复 | `project-recovery-owner.test.mjs`、`project-recovery-owner-electron.test.mjs` | 先检查原有平台假设，再覆盖真实 Electron 的实例占用与失败保留 |
| 实际桌面 | `test:smoke` 与文档/窗口场景 | 在图形会话中验证启动、编辑、退出和冷重启；现有 smoke 主要验证文本文件，不代表格式清单通过 |
| 文件格式与操作 | 文首 MVP 清单及现有 PDF/图片/Word/Sheet/PPT/文本编辑测试 | 逐项映射合成夹具，在最终安装包验证保存、重开、批注锚点或导出副本；记录内容核验结果、截图与失败日志 |
| 私有原生运行时 | 当前 `test:live` 是显式启用的本地脚本化响应测试，无账号、无付费模型 | 按普通执行/隔离能力拆分，核对 node-pty 在 Node 和 Electron 下的加载条件 |
| 真实模型 | 另行选择并审查测试入口 | 明确授权后执行；没有结果就标记未验收，不根据文件名含 live 推测是否付费 |
| 安装包 | 最终 dmg 安装出的 `.app` | 验证打包布局、签名、完整性、内置工具和独立配置；源码运行结果不能替代 |
| 升级与回退 | 阶段 6B 的版本对、兼容结论及合成备份 | 完成 A → B → A 和失败保留；应用包保留测试不能代替用户数据恢复测试 |

CI 选择明确的 macOS 镜像及架构，并在任务中输出实际系统和 CPU 信息；不能只凭 runner 标签推断。先接入干净构建与无模型 smoke，再加入已完成平台适配的安全和恢复回归。图形会话是否可用、窗口测试是否稳定，都需要实测。

每次验收记录源码提交、锁文件/产物摘要、系统与架构、命令、通过/失败/跳过/未执行数量、明确的跳过原因和待办。MVP 必测用例被跳过不能算 MVP 通过；特殊项目恢复保持不可用时，完整平台验收仍未完成。

## 4. 里程碑与工期管理

| 里程碑 | 退出条件 | 工期处理 |
|---|---|---|
| M0：摸底 | 阶段 0 有可复核记录，已知阻塞项有清单 | 可先安排 1–2 个工作日作为调查时间盒；不是保证完成适配 |
| M1：关键路线验证 | OMP 实际启动、安全文件完整操作链（含目标卷文件名等价与冲突拒绝）、可靠进程身份原型通过；特殊恢复明确可行路线或保留禁用 | 逐项记录实际耗时与剩余风险，再估实现工期 |
| M2：开发验证版 | 基础协作、停止、正常重启及安全回归可重复通过 | 不包含用户安装交付，不称为 MVP |
| M3：macOS MVP | M2 + 系统集成必需项 + 最终 dmg 上全部 MVP 格式必测项 + 指定版本间升级/数据回退 + 对应 CI；排除项明确可见 | 通过 M1 后给出基于范围的区间；包含打包、格式验收与回退演练时间 |
| M4：完整平台验收 | 所选系统/架构上的路线清单完成，包含特殊恢复与权限场景 | 缺项持续保留，不能仅凭 CI 全绿关闭 |
| 后续增强 | Intel/universal、显式隔离、正式签名/公证及公开分发资格 | 各自独立评估，不自动并入 MVP |

执行关系：阶段 0 后尽早验证 OMP、文件原语、进程身份和特殊恢复的关键未知项；它们不全部依赖 OMP，基础阅读验证也不依赖 OMP。关键原型通过后完成各模块集成，最终以安装包验收收口。测试设计贯穿各阶段，不能留到最后才发现关键用例一直被跳过。
