# 正式任务工作区设计

## 主对话与 Worker 对话：下一回合与等候队列

[可交互 Demo](demos/task-conversation-queue/index.html)；仅浏览器内模拟，未接宿主或安装。右侧 Work 与报告「审核讨论」进入同一 Work 对话，报告入口定位发布事件；主对话独立归属，二者共享输入交互，不共享队列或草稿。用户消息、回复、报告按时间排列，工具过程原地折叠；实时更新只在贴底时跟随。

工作区 Demo 沿用产品 slate 主题、左侧项目轨／文件树和右侧「待你决定／工作追踪」。点击工作行打开非模态 Worker 悬浮窗，不新建中部标签；待办仍打开独立报告，报告底部「审核讨论」激活同一悬浮窗并定位发布事件。标题栏可拖动、收起、关闭；关闭只隐藏，草稿、队列、展开和滚动位置保留。底层主对话、文件或报告保持原位。模拟执行控制单独放在右栏。

工作区版 Chromium 验证：右侧任务与报告底部复用同一非模态窗口；打开时底层对话、文件或报告保持原位。桌面可拖动，收起／关闭后重开保留位置、草稿与过程展开，审核入口定位到发布事件；主对话草稿及 Worker 队列互不影响，390px 下悬浮窗不横溢出。

- 输入框只保留原有动作：主对话「发送／后台任务」，Worker「发送」。有正文时 `Tab` 加普通队列尾；`Enter` 或「发送」优先于普通队列、同级按提交顺序，不打断当前回合。空闲时 `Enter` 直接开始；`Tab` 仍只登记，由演示控制显式启动。`Shift+Enter` 换行，`Shift+Tab` 保持反向焦点，`Esc` 后的下一次 `Tab` 可离开非空输入框；IME 组合期间不提交。「后台任务」单独登记模拟任务，不进入前台对话的待发队列。
- 故障时同窗显示失败轮、回执与两级待发队列，允许输入并保存补充；不把入队当作恢复。只有退出／效果可核实时，用户才可显式让原 Work 从新指令接续；这条恢复指令先于旧队列，旧失败轮不重放。效果未知时接续保持禁用，须先核对。恢复不采纳／合入成果，也不改变原权限或冻结证据。
- 生产实现需区分宿主持久排队、原生准入与未知回执；现有 `queueJob(priority)` 会插到首条非 initial 等候项前，多条优先项可能反序，且没有仅登记不启动的语义，不能直接套用。建议复用宿主队列和单 owner 准入，增加同级 FIFO 与明确放行条件；审核发送仍校验确切对象／版本，历史对象不升级权限。不得同时写入宿主与原生的两层待发队列。

生产设计经独立窗口及调度审查：同 Work 由可信工作区持有单个原生非模态子窗，报告入口只携带确切发布绑定；历史窗口只读。队列按项目实例＋会话归属，普通与优先各自 FIFO，准入提交是排序边界；未确认旧回合退出或效果时不执行等待项。提交、已送达和已结算分开呈现。队列操作不授予审校、合入或故障解锁权限。

### 报告「追加讨论」：原生弹窗复审

报告按钮及入口提示已更名为「追加讨论」，内部 IPC 与审核授权不改。Linux X11 源码构建通过；隔离 Electron 实测看到了新文案，但冷开只完成子页挂载，首次关闭操作前等待原生可见性超时。出错快照：子窗不可见且未聚焦，父窗可见但未聚焦，报告页无报错（`/tmp/nozeli-approval-discussion-PhDt6d/report.json`）。本轮没有通过全旅程，也未安装。

两位内置 reviewer 判定首要缺陷是显示回执：`NativeReviewDiscussionManager.show()` 只在父子窗口已有焦点时尝试聚焦，可能返回 `{shown:false}`；报告页却把 IPC 成功当作已展开。现场证据不能确定是谁夺走焦点，也不能区分窗口未显示和短暂显示后隐藏。第二个缺陷是重开恢复位置、定位发布事件、异步刷新分别写滚动位置，且发布定位不保证 React 已提交；不把静态风险写成实测跳动。

- **先改显示握手。** 只有显式点击触发显示。同一个入口的在途请求合并，按钮立即显示「正在打开…」；校验当前启动入口、确切报告版本、子窗和同代几何后，宿主返回实际已显示、未显示（如切到其他应用）或失败，页面据此更新状态。应用仍在前台才激活；后台不抢焦点、不延迟回弹。关闭保存成功才隐藏并归焦当前有效入口，失败留窗和草稿。统一打开、重绑、关闭意图，旧结果不得覆盖新选择；保留单 Work 一个可写窗及现有版本授权。
- **再改阅读定位。** 从某版报告首次进入时，在目标 DOM 提交后定位该版发布；同一入口重开恢复原消息锚点和相对偏移，已显示则只激活。每次只执行一个滚动意图；用户手动滚动、选区或 IME 准入时不被迟到的刷新覆盖。目标不在当前页时提供查阅更早记录的入口，不假装定位成功。
- **统一版本行为。** HTML 和 Markdown 都保留当前版；新版只提示，显式「查看最新报告」才打开对应报告面，不改旧页和草稿。历史只读不因打开取得发送能力。打开、重开及定位均不发送、派工或重放。
