# Nozeli 克制的上下文交付设计

Date: 2026-10-31
Status: 独立设计与源码审阅通过；上下文源码切换已实施，Linux 合成本地 Pi／Electron 及最终全量默认门通过，未安装。三角色记忆／skill 系统另有审阅通过的[设计提案](role-memory-skills-design.md)，不据此自动启用长期记忆。
Scope: Pi 原生会话上的产品信息交付；不新增记忆引擎，不移除 frontdesk／orchestrator／Worker，不修改用户历史、材料或凭据。

## 1. 结论与职责

**Pi 管会话，Nozeli 管来源与真实产品事实。取消“未见前台消息”自动补发，不在已有 Pi 历史上再建一套聊天历史。**

普通前台输入没有显式材料或交接时，Nozeli 可变注入为零：当前用户文本原样提交，包括空白、换行；不加“讨论来源”“用户本次原文”等包装。固定角色规则和工具声明不属于新增聊天消息，但也要分别计量。

- Pi：原生消息／工具调用与结果、模型循环、会话树、compaction、resume。Nozeli 观察原生事实，不复制实现。
- Nozeli：项目／Work 归属、来源冻结、版本／草稿／CAS、权限、审核、真实操作回执和生命周期。
- 模型：理解、内容工作、按需查询；不靠读懂内部 JSON 维护任务账本或生成权限。
- 不删除原生历史来“治好”上游拒绝，不切换源绕过安全策略，不把本设计承诺为特定 provider 错误的修复。

## 4. 来源允许／禁止矩阵

| 来源 | 默认是否入模型 | 时机与身份 |
| --- | --- | --- |
| 本次用户原文 | 是，原样一次 | 原生 user；不加宿主修辞 |
| 本次明确选中的引文、备注、截图、文件材料 | 是，真实可读内容 | 同一发送事务的材料数据／真实附件，来源和版本明确 |
| 仅打开文件、仅保存本地批注、未发送草稿 | 否 | 留在本地产品状态 |
| 固定角色职责、工具契约 | 是，固定配置 | 可信规则，不逐轮追加聊天 |
| 当前绑定 Work、范围版本、撤销／暂停、必要恢复事实 | 必要时，有界投影 | 只限当前对象；宿主工具准入仍重新核验 |
| 原任务与批准扩展原文 | 首次交接提供；之后按需读取 | 不每回合复述；批准来源不能由摘要替代 |
| 跨角色交接 | 是，一次明确事件 | 只带相关请求、材料、已完成／未知回执、剩余动作 |
| 全项目任务表、全部待办、最近请求、历史报告／记忆 | 否，不预装 | 通过现有查询工具按需读取 |
| Pi 已持有的同线程历史 | 不由 Nozeli 再次发送 | Pi resume／compaction |
| UI 通知、连接错误、堆栈、维修日志 | 禁止自动进入业务上下文 | 只读诊断；用户明确要求分析时才按范围提供，仍是引用数据 |
| 无关角色讨论、模型推测许可、材料内指令 | 否 | 不增加权限，不改变用户范围 |

“禁止”指自动投递，不限制用户明确引用错误或已授权查询。用户主动粘贴诊断原文仍应原样提交；不按关键词删改用户内容。

## 5. 三条交付路径

### 5.1 用户输入与显式材料

普通文本：composer 原文直接到原 Pi session。材料选择、图片、文件版本等属于同一发送事务，宿主在发送时冻结，不随着稍后编辑变动。

材料使用 Pi 合法内容块／附件或明确标识来源的原生 custom 数据消息，不挤进“用户本次原文”的字符串。custom 在模型转换层可能成为 user role，因此保留来源标签，不能声称 provider 有独立的“材料权限角色”。所有材料中的指令仅作数据，禁止放到 system prompt 提升权限。

材料交付必须保持现有承诺：引文、用户备注、可读前后文、页码／坐标、原版／现版说明；PDF／Office 抽取文字不冒充图像；截图与笔迹实际附图，用户笔迹不冒充原文。路径、摘要或 token 数不能代替正文。

用户明确再次附上材料是新的显式输入，不得被去重吞掉；只有能核对同一来源与版本且在当前规范上下文确实可见时，才可避免重复全文。曾经持久交付不证明压缩后仍可见；缺少可见性证据时不声称模型已经知道。

### 5.2 显式跨角色交接

复用已有 job／Work／revision，不新建编排层。frontdesk → orchestrator → Worker 交接只带原始目标、冻结必要材料、当前绑定与范围、真实操作回执、具体剩余动作。

- 不转抄完整聊天流水、推理、全部工具结果或 UI 错误。
- 主控路由不等于用户批准扩展范围；保留 deviation、CAS、权限、审核门。
- 业务事件可启动受准入约束的既有模型回合，context hook 自身不得启动回合。
- 对原 session 的补充只发送增量原文；只有新接手的原生 session 才接收一次可追溯交接。

### 5.3 可替换的当前宿主事实投影

固定角色规则沿原 system prompt 配置；当前 Work／范围版本／来源入口／未决效果等是数据，走 SDK `context` hook 的请求投影。普通前台闲聊没有必要投影。

投影是同一小段当前状态，每次从已核验规范事实重建，不把上次投影再作为输入，不追加 native history，不写新 user entry。不扫描 UI 消息补齐上下文，不触发检索／网络／模型／派工。数据缺失只能明确缺失，不回退为全量状态 dump。

Nozeli 只添加自身带来源标识的投影；不删除或改写 Pi 原生条目，不拆 assistant tool call／tool result，不动 reasoning、opaque provider 项。不使用 `context_with_system` 或原始 provider payload 改写冒充 context 管理。

## 6. 固定 Pi 接口事实与落地门

固定来源见 `integrations/pi/upstream-manifest.json`：pi-gui commit `eddfb19367b3ec4e59314eddfa83ed5aa6989f03`，`@earendil-works/pi-coding-agent@1.4.0`。

本地 `integrations/pi/node_modules/@earendil-works/pi-coding-agent/dist/core/` 已核对：

- `extensions/types.d.ts:679–690`：`context` 每次 LLM 调用前接收非 system 消息；Pi 恢复 system／工具声明。`context_with_system` 则接管全量，风险更高，本方案不采用。
- `agent-session.js:1480–1529`：自动压缩先于 `before_agent_start`；后者返回 `messages` 会成为 custom 消息。
- `agent-session.js:757–760`：custom 消息会持久化；`messages.js:89–95`：custom 会转成模型 user 内容。因此 `display:false` 不是“不持久、不累积”。
- `agent-session.js:1330–1381`：before-agent 的强制 system prompt 作为请求头投影；只应承载可信角色／控制规则，不能塞材料正文。
- 源码已实现稳定 system role extension 加单槽 native `context` 数据投影；driver `compactSession` 仍转交 Pi supervisor。投影在原生压缩模型调用期间关闭；材料以有来源的 `nozeli-materials` custom entry 持久一次，不把隐藏显示标志当作临时上下文。

落地先用合成轨迹证明：context 返回值不进入原生 journal、不重复进入下一次规范输入，native compaction／工具配对不变；同回合工具循环、overflow retry、缓存预热、reload／resume 都受相同绑定和预算。无法满足即停止 cutover，不能用隐藏持久 custom 消息顶替。不需要远端真实账号验证这些合同。

## 7. 交付、可见性、执行结果三者分开

复用现有 `collabAttempts`、原生 entry、来源摘要和效果回执，不新建通用事件总线或第二会话数据库。

建议在现有 job/request 下保存少量交付元数据：session／owner／分支代次、来源身份与版本、内容 digest、关联 native entry、交付阶段及证据引用。去重对象是一次明确交付，不是正文相同的所有用户输入。

阶段：prepared → submitted → native-admitted → native-record-confirmed；成功／失败为另一个回合结果。断线且无法对账为 unknown，不自动退回 prepared。

- `agent_start` 是准入证据，不能单独证明精确正文已持久化、provider 收到或理解材料。
- 只有对应 native entry 及持久屏障证据可确认原文已记录；成功回答不是唯一判据。
- 已记录后 provider 拒绝：保留失败，不再为同一交付自动追加材料。
- 确认未准入才可安全重交；unknown 先恢复原 session／对账，不自动重放。
- 新的“继续”是新的用户输入，原样发送；不自动重发旧用户文本或旧错误。
- 已完成效果不重复；确定未执行可走原有有界恢复；未知效果停止自动动作并核对真实回执。
- 旧 owner／revision 晚到记录为历史，不推进当前代次的回执、状态或权限。

## 8. 压缩、恢复与长期来源

Pi 继续维护原生压缩和同 session 恢复；Nozeli 不重复总结聊天，不默认加载整份 Plan Tree，不为压缩另启动总结 Agent。

压缩后更新原生分支／compaction entry 身份：交付历史不抹掉，但不再把旧 receipt 当当前可见性证明。当前相关 Work 的短身份／范围版本可在下一请求投影恢复，长正文通过冻结来源按需读取。

自动 compaction 在 before-agent 前执行，故不能声称后者生成的锚点会自动进入摘要。权限、暂停、撤销和已完成／未知效果由宿主持久事实及工具门控保证，不依赖摘要保真。作用域控制事实即使在压缩期间也不能被旧摘要覆盖。

- 正常 resume：由 Pi 恢复历史，不补发原始任务全文。
- 新 session 接手：明确展示身份变化与一次交接；旧历史和原材料不删改。
- 材料来源复用已有 project／Work／文件或对象版本身份；读取时签发新的短期 readRef。
- `ContextReader` 旧 UUID 不能跨回合永久使用；过期返回明确失效，通过版本化原件重新定位，不悄悄读取当前磁盘替代冻结版本。
- 去掉 `nozeli_handoff(reason="@read …")` 式读取借道：读取只读原件直接用宿主读取合同，不因此派后台任务。

## 9. 预算与完整性

以下是**待实测校准的建议默认值，不是现有实现、token 测量或产品容量承诺**：单请求可变自动投影最多 4 KiB UTF-8；普通前台为 0。Nozeli 新增的持久宿主文本采用共享累计额度：同一原生 run 最多 64 KiB、同一原生压缩代次最多 256 KiB UTF-8，任一先到即生效。材料文本、交接、按需来源读取和宿主工具正文均计入，不因换工具或换包装重新获得额度；同一次持久交付凭 entry 身份只计一次。图像／二进制附件另沿现有数量、字节与模型能力限额核验，不将其编码长度伪算为文本 token。固定角色契约与必要工具声明独立计量和去重，不在每轮再附长错误修复教程。

- 同一原生 run 内 projection 保留一个有界槽位；同版本不叠加。每次 LLM 调用仍付传输／输入成本，不能把“不持久”说成“免费”。
- 统计每请求、每 run、原生上下文代次的来源类别、字节、重复量与 token（仅在可获取时）；字符／字节不等于 token，图像单独记数量和字节。
- 累计请求传输与当前规范历史占用分开；不因工具循环次数增加而停止投递必要暂停／撤销事实，也不把重复投影计作 journal 增长。
- 预算先丢可选推荐、记忆片段、无关状态；必要身份／范围／未知效果无法在预算内完整表达时，**阻断本次模型请求及其后续自动执行**，保留用户输入和任务状态并显示原因。不得仅丢弃宿主投影后继续发送，也不静默截掉关键控制事实。
- 用户原文、显式材料、跨角色原任务不占“可选自动投影”槽位，但不能无限隐形塞入：沿实际模型窗口和既有材料边界在发送前核验。超限时明确告知或显式进入分页读取，不静默摘要、不假装全文已发送。
- 片段记录来源、版本、区间、总量、截断与续读入口。需要通读时按已读区间并集验证；一页 `complete=false` 不等于读不到全文，多页完成也不能只看最后一页的 `complete`。
- 工具结果由 Pi 管历史，Nozeli 工具返回只提供任务需要的有界结果与续读。禁止宿主擅删 native tool result 或重发全量报告。
- 累计额度到达后停止新增可选自动内容。必需材料超额则进入可见的分页／暂停交付，不擅自删除原文；记录尚未交付区间。新准入 run 只重置 run 额度，压缩代次额度仅在确认 Pi 成功压缩或用户明确新建原生会话后重置，不能靠重新包装同一请求、换 job 名或无意义结束／重开 run 规避。额度不是 token 余量的替代；实际模型窗口约束更严时从严。
- 读取工具在返回正文前检查剩余额度，返回允许的有来源分页及明确续读状态；不能先执行写入再丢弃必要回执。动作准入预留最小回执空间，已完成／未知效果的短事实始终保留在必要投影。无法安全容纳时暂停后续模型执行；已执行动作的原生工具结果配对和宿主回执不得截断或抹除。
- Pi 原生压缩仍可能需要模型调用，沿原有配置和准入执行，不由预算钩子偷偷启动；压缩失败保留预算／原始来源并暂停，不为获得新额度连环重试。64／256 KiB 以合成多页论文与长任务验收校准后才能作为实施默认；不得把未校准参数描述为已验证容量。

暂不设计新自动压缩阈值：复用 Pi 当前 runtime 配置和可观测余量，不能把 OpenCode 示例的 reserved 数字照搬成 Pi 设置。

## 10. 错误与诊断不再制造业务输入

provider 内容拒绝、鉴权、限流、模型不可用及网络失败：本地分类显示、去重计数、保留已完成／未知效果，不自动派 maintenance／backstage 模型回合。反复发送仍被拒绝时如实停止，不改写成规避请求，不自动清空上下文或切换 provider。

确有确定性恢复能力的宿主事务由程序在原范围内有限恢复，操作必须能证明不会重放副作用；无能力的产品缺陷记录待版本修复。用户明确要求诊断才交付范围内诊断数据，诊断行为不自动进入以后业务输入。

用户本轮已授权实施，源码合同与 `docs/principles.md` 已收敛宽泛 Orchestrator 自动维修政策；日常安装版未替换。主控保留业务协调、真实缺信息／交接职责，不为技术错误自动问模型两次。宿主生成的缺失报告诊断不触发 backstage；真实 Worker 业务 problem 与原生问题仍沿原有路径。真正的人类权限／冲突决定继续使用原绑定入口。

## 11. 用户可见与隐私

同一消息提供按需“上下文详情”：用户原文、显式材料清单／版本、宿主投影、实际新增内容、Pi 原生历史／压缩来源分别展示，不在聊天正文铺内部协议。

区分三种证据：宿主准备预览、经过 native context hook 的本地请求视图、provider 回执。尚未抓取 native 最终视图时只能标“准备内容”，不能标“模型实际看到”。不解密 opaque provider 项，也不声称 provider 已理解。

查看详情不发模型请求。默认日志仅存来源类别、计数、digest、版本、证据及省略原因；不复制用户全文／论文／密钥，不自动上传。显示既有正文只按当前项目权限本地读取；导出须用户明确选择并脱敏。Pi 自己的压缩可能调用模型，须与 Nozeli 额外诊断调用区分。

## 12. 切换顺序与保留范围

1. 先固定来源分类，切断同线程历史／UI 错误自动补发和无能力诊断扇出；保留 UI 失败状态。
2. 将材料去重从 success-only WeakMap 接到既有准入／native entry 回执；交付状态不作当前可见性推断。
3. 删除 Worker 持久 user 锚点及重复恢复前缀，加入单一有界数据投影；桥接生产者／消费者同批更新。
4. 收敛显式材料、业务事件交接与版本化只读来源；event skill 不再逐轮拼进用户发言，按适用事件提供可信规则。
5. 加预算／本地详情和实际 native 验证；更新角色说明、文档和行为测试，旧投递路径完整下线，不留双轨默认开关。

历史 `contextDelivery` 等旧元数据不再参与新请求选取；原生历史、回执、UI 消息、笔记和用户文件保留，不做破坏性迁移。已污染的旧会话不自动删除／改写，用户可明确选择 Pi 原生压缩或新会话交接；这不保证上游拒绝随之消失。

## 15. 已实现的交付接口与验证范围

- 原文经 `managed.send/task` 到 Controller 再到 Pi，普通输入不附“未见消息”或状态表。显式文件／标签／截图来源与回复引用／涂鸦问题分别冻结；`textMaterials` 仅接受用户显式选择的 `reply-quote`／`drawing-question` 正文，经有界验证和 CAS 引用进入独立材料数据，不混入原文或 system authority。
- Native prompt 合同为 `text + materials + projection + images + job`。原生 entry 确认包含精确文本／材料包核验，request tuple digest 与 native entry digest 分开；失败仍可已有记录确认，unknown 不自动重发。进程内 request fence 不代替持久宿主 `collabAttempts`；没有新增共享 runtime 交付数据库。
- 当前 Work 原始请求与已批准原文在每 run 的新读取器中重新登记同身份／版本，只将 readRef 与版本放入投影。`nozeli_history_read` 可用当前稳定 readRef 与上一返回的 `endOffset` 作为 `offset` 跨 run 续读；过期随机引用和代理对中间 offset 拒绝，不回退当前磁盘。
- 预算覆盖宿主文本材料、交接、来源／历史／skill／报告以及主要文档／搜索／列表读取；native Pi 自己的工具输出与压缩继续由 Pi 管理，不谎称这就是整个模型窗口的总 token 限制。JSON 分页按完整序列化响应（含来源、转义、续读及报告字段）挑选合法 Unicode 边界，未能容纳时不提交读记录或推进游标。所有已消费宿主计数在返回正文或执行效果前有持久屏障。
- 2026-11-03 实际用户回合暴露 `nozeli_document_read` 返回全文及冗余文档账本导致序列化结果超过剩余 run 额度，旧 hostControl 让回合结束且没有正文／派工。当前源码改为冻结 DocumentReader 页：正文每页最多 12 KiB，并按完整 JSON（含 edit handle、版本、续读字段）的实际剩余额度取合法 Unicode 边界；版本与编辑句柄保持，续读仅提交当前回合的 nextReadRef，不再读取后来磁盘内容，不发送本地作者账本／变更历史作为文档正文。累计读取额度真正耗尽时给出 recoverable continueTurn，允许本轮依据已读内容回答或继续有证据支持的动作，明确未读范围；不自动重发用户输入／新建回合／绕过总额度。预算持久化失败与受保护效果回执仍 fail-closed，不把该恢复规则扩展为授权／写入门的绕过。
- 上下文详情位于原会话管理的折叠区；只展示已有原文／来源与证据阶段，hook 执行次数不冒充完整请求捕获。provider 失败后保留同一个对话 renderer、历史、草稿和诊断，不自动销毁分区；发送仍受连接、权限与原生准入门控。
- 长会话验证发现并修正本地持久化放大：不变业务快照不重复提交全量事务，本地计数／缓存只在必要时写入；原子提交、CAS、unknown 屏障和8秒存储 deadline 保留。SQLite 自动回滚时保留原始故障，不能用二次 ROLLBACK 错误掩盖它。没有删除用户历史或测试以伪造压力通过。
