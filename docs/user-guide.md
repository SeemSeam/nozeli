## 安装（免源码、免 Node.js）

前提：Linux x86_64/glibc 桌面会话与 Electron 所需系统库（图形、音频、NSS 等，多数发行版自带）；普通桌面用户权限。当前 Electron 原生 Wayland 剪贴板存在上游缺陷，建议在 Wayland 桌面保留 XWayland（提供 `DISPLAY`），由启动入口自动选择可靠后端；没有 X11／XWayland 的纯原生 Wayland 环境尚不能保证系统复制可用。

```sh
# 1) 从发布页下载 Nozeli-<版本>-linux-x64.tar.gz 与 SHA256SUMS.txt
cd ~/Downloads
sha256sum --ignore-missing -c SHA256SUMS.txt # 应显示Linux归档OK；校验和只能发现传输损坏，不等同签名或来源认证

# 2) 整体解压到有写权限的目录（保留可执行权限）
mkdir -p ~/apps && tar xzf Nozeli-0.1.0-alpha.1-linux-x64.tar.gz -C ~/apps

# 3) 运行（新构建的 AppRun 优先 DISPLAY/XWayland，再选原生 Wayland）
~/apps/Nozeli-0.1.0-alpha.1-linux-x64/AppRun
```

- 无需 Node.js、npm、系统 OMP、Git 或源码编译；这些已随包提供。
- 整个文件夹可移动，但不要单独移动文件夹里的文件。
- 以普通用户运行；不要以 root 运行，不要用 `--no-sandbox` 绕过安全限制。若发行版限制无特权用户命名空间，由管理员按发行版策略配置 Chromium sandbox；本包不自动提权。
- 单实例：重复启动会退出并把打开请求转交已有实例。
- **系统文本复制**：选中文字后使用 Ctrl／Cmd+C 或“编辑 → 复制”；本地文档、代码、PDF、Office 与对话共用真实系统剪贴板。当前 Linux 启动入口优先 X11／XWayland，避免 Electron [#54645](https://github.com/electron/electron/issues/54645) 的“应用内读回成功但外部内容未更新”问题。更新后须退出全部旧窗口再从桌面入口重开，不能通过应用内刷新修复旧进程。若直接调用二进制，在有 `DISPLAY` 的桌面显式传 `--ozone-platform=x11`；显式原生 Wayland 仍保留上述缺陷边界。已发布旧包不因本文更新而自动改变。

## 升级、回退与卸载

- **升级**：先正常退出 Nozeli（见“退出问题”），再把新版本解压到**新目录**运行；旧版本留在原处即可回退。升级不覆盖运行中的文件。
- **回退**：退出新版本，运行旧目录的 `AppRun`。
- **卸载**：删除解压文件夹即移除程序。配置与会话在 `~/.Nozeli`、批注在项目内 `.nozeli/`，都不会被删除；确认不再需要时手动删除 `~/.Nozeli`（重置应用配置与会话）。
- 从源码开发的用户级安装（`~/.local/opt/nozeli` 的 `current`／`previous` 指针）是另一条开发路径，见[桌面开发说明](../apps/desktop/README.md)。

## 数据位置与备份

| 数据 | 位置 | 内容 |
| --- | --- | --- |
| 项目数据 | 项目目录下 `.nozeli/`（隐藏） | 批注与讨论锚定、修改账本与作者标记、对象存储、受管项目元数据 |
| 应用数据 | `~/.Nozeli/` | 应用配置（含私有 AI 源配置与账号）、会话与工作区状态（桌面 profile 在 `~/.Nozeli/desktop`） |

备份方法：**先完全退出 Nozeli**（全部窗口关闭、后台任务结束或停止），再复制两处——项目目录（含 `.nozeli/`）与 `~/.Nozeli`。应用运行中持续写账本与日志，运行中复制的快照可能不一致。不要手工编辑这两处内部文件。

### 项目入口图标（源码已更新，未安装）

左侧项目入口使用居中的项目名缩写：单个词取前两个字素，带空格／下划线等分隔的名称取首尾词首字，拉丁字母大写；缩写冲突时加数字区分。当前登记集合内按项目身份确定冲突编号，不随打开时间排序变化；新增／移除同缩写项目可能重新编号。大写展开或冲突编号超过两字素时按最终字素数缩小字号，不裁掉字符；完整项目名继续通过悬停提示与辅助技术名称提供。

项目图块不使用身份配色，统一沿用当前主题的中性文字与纸面色：缩写默认上限为 11px、字重 500，大写展开或冲突编号较长时继续缩小。文字采用 80% ink 与 20% paper 混合，不直接使用 muted；图块底色仅混入 2% ink，保持轻底与弱边线，让项目入口退居内容之后。当前项目使用略深的中性底、细边线和左侧短标记；悬停加宽同一条边线，按下进一步收小图块圆角，不产生位移、阴影或双框。仅键盘焦点沿用主题焦点色的独立虚线框；目录不可用时图块边线改为虚线，完整提示仍说明原因。

44px 点击区内保留原位 32px 图块与 6px 内缩；真实待办显示右上角 16px 红色数字角标，超过 99 显示 `99+`。红色仅用于原有待办状态提示，不表示项目身份。角标与缩写上下分区，辅助技术仍读取完整名称与真实待办数量；系统强制颜色模式采用系统色并保留边线、选中短标记及焦点形状。点击、待办键盘入口与项目切换行为不变。本轮Linux源码四主题及交互态验收通过，实测小字有效底色对比度最低5.48:1，截图与交互证据见当前状态；Windows/macOS与日常安装不在本轮验收范围。

### 将项目重置为新项目

在左侧项目入口上右键，选择 **“重置为新项目…”**，核对范围后点击 **“归档并重置为新项目”**。取消不会重置。此功能与“清理本机项目数据”（仅清理视图）不同。

- 保留该目录内的实际文件、Git，以及全局账号、API 源与模型设置。
- 先保留未保存内容、停止该项目的任务与终端，再归档旧批注、讨论、会话、任务、草稿、布局和执行状态；保存或停稳失败时拒绝重置，不强行清空。
- 同一目录以新的 Nozeli 项目身份重新加载，不继承旧状态、不重放旧任务。未保存稿仍属于旧项目恢复记录，不会自动写入原件或带入新项目。
- 旧执行实例原位封存，避免移动 Git worktree 或原生会话路径。归档位置内 `reset.json` 列出元数据副本、旧实例与恢复区的实际路径；若需完整备份，应在退出应用后连同清单指向的目录一起保存。
- 确认窗口和完成提示提供归档位置。归档不等于永久删除；不要在 Nozeli 运行中手动覆盖内部目录。当前功能不提供一键恢复旧项目，旧未保存内容可在设置中的恢复中心核对与导出。


## 配置 AI 源（不随附任何密钥）

1. 首次启动可选“稍后设置，继续阅读”——不配置 AI 也能完整阅读、批注、编辑本地文档。
2. 需要协作时，在设置中配置**你自己的**模型服务、账号与三角色（前台／主控／Worker）默认模型。本分支使用独立 Node 进程承载 Pi，不读取系统 OMP 配置；启动、阅读与 Host 文件工具不要求系统 Pi、OMP 或 Bash。原生命令工具的平台依赖以及 Windows/macOS 尚未实测签收。
3. 发行物不含开发者密钥、OAuth 或个人数据；API 密钥保存在 Nozeli 私有 Pi 配置和认证存储（权限 0600），设置读取接口不回传密钥。
4. 模型请求仅在显式操作后发生；无联网遥测。

### 会话、模型与思考档位

- 对话时间线就是 Agent 会话本体：用户与 Agent 的消息、推理、工具调用与结果按事件流显示；执行中的流式内容是临时投影，最终以持久会话条目为准。工具调用默认折叠，点开查看参数与输出原文。
- **消息执行状态**：前台收到输入后即显示排队／启动状态；有实际回合和工具事实时显示思考、工具执行、等待或输出，终态显示完成、失败、中断或受阻。折叠执行过程仍能看见状态和待完成工具，旧回合不会随下一轮活动重新变成执行中。用户气泡不显示 Agent 输出状态；同一次输入的原生确认回显不重复成第二条消息，真正再次发送的同文输入仍分别保留。模型只使用该回合的实际生成记录，包括宿主成果摘要所绑定的已完成原生回合；关闭或休眠后不拿当前设置倒填历史，没有确切记录时仍显示未记录。
- Worker 成功交付成果时显示“已交付 · 待审核”，续作后原轮显示“已交付”；这不表示成果已接受或工作已收尾。已纠正的早期工具错误仍可展开查看，不会把有冻结交付凭据的成功回合误标为失败；真实失败、中断和未知结算仍如实显示。
- **历史报告版本（源码补修，待安装）**：旧报告保留自己的发布版本、候选和续作记录；不会因同一工作的新版本被接受而显示为已合入。历史版只读，界面另行标明当前工作版本；接受与收尾仍绑定确切对象和审核令牌。
- **对话宽度**：消息、执行状态和输入框随当前对话分区的实际宽度伸缩，不再被固定阅读列限制在窗口中央。放大窗口、拖动分屏、脱离独立窗口及移回时沿用同一工作面；窄窗保持边距、自动换行和可见的发送／提交后台按钮，不重置草稿或选区。
- Agent 的原生 OMP 终端已随 Pi 迁移移除：没有接管或“接回终端”入口，也不会伪造终端画面；旧布局保存的终端窗格仍显示迁移说明。左侧“终端”是独立的普通用户 Shell，不启动 Agent。
- **模型与账号源（2026-10-31 更新）**：设置 → 账号与 API 源支持多模型自定义源（每行一个模型ID；行尾加 `[thinking]` 声明该模型支持思考）、编辑与密钥轮换（编辑时密钥留空＝保留已存密钥，密钥永不回显；API 地址来源变化时复用原密钥需明确勾选确认）、修订号防覆盖，以及显式"发现模型"（仅调用该源的模型列表接口：OpenAI 兼容 `GET {baseUrl}/models`，Anthropic `GET {baseUrl}/v1/models`；有界超时／大小／页数，拒绝重定向，404/405 明确报"不支持列表查询"，401/403 报授权失败；成功列表只证明可列出，不代表推理授权，且从不发起对话来测试凭据）。凭据已配置、内置目录或服务返回都不等于服务端授权；是否可实际调用以服务端为准。默认模型每角色可选模型＋思考档位（清除即恢复会话原生默认并取消排队中的切换）；保存后在线会话在安全空闲边界应用并回报每个会话的期望／实际生效档位（原生收窄会明确标注）。源保存／轮换后，使用该源的在线会话在空闲边界用同一选择器重新解析凭据，不新建会话、不重放输入。真实账号 OAuth 登录仍需真实账号参与，未在自动化中验收。
- **账号登录与内置源密钥（2026-10-31）**：设置 → 账号登录列出运行时实际支持的 OAuth 源（原生 Anthropic、GitHub Copilot、Kimi Coding、Meta、OpenAI、OpenAI Codex、OpenRouter、xAI 及新增 Z.AI GLM Coding Plan；列表来自私有 Pi 运行时能力，不是固定名单）。Z.AI（GLM Coding Plan）登录流程：确认提示 → 在自己的浏览器打开授权链接完成 Z.AI 登录 → 手动粘贴最终 `zcode://zai-auth/callback?...` 回调或 `code#state`（Nozeli 不注册、不接管 `zcode://` 系统回调，裸 code 不接受）→ 成功后创建/复用名为 `nozeli` 的专用 API 密钥（不改 ZCode 自身密钥），密钥持久保存在本机私有认证存储并直接用于 Pi 请求与模型目录。取消会中止在途网络请求；错误只显示阶段与状态，不回传服务端原文或凭据。“内置源 API 密钥”表单可为运行时声明支持密钥设置的原生 Provider（如 openai、google、openrouter、zai 等）直接保存 API 密钥，模型定义随运行时提供，无需手填模型；已保存订阅登录的源需先退出登录才能改用密钥。真实 Z.AI 账号登录尚未实际运行验收。
- “会话管理”提供真实会话状态、只读原生诊断、手动压缩上下文、重载运行时资源及停止当前回合。压缩／重载仅空闲时可用；停止绑定显示的原回合，不结束 Work、不撤销已完成修改，也不取消已排队的下一轮补充。旧菜单或旧回合不能操作新会话。
- **紧凑 Agent 栏（源码更新，待安装）**：输入框下方一行显示 `F`（前台）、`O`（主控）、`W1…`（各工作 Agent），点击字母直接选择该 Agent 的后续回合模型。状态点以颜色和形状区分执行、等待／待审、失败、休眠及未知；悬停或辅助技术可读完整身份、任务、状态和实际模型。更多 Agent、计时、刷新与修复诊断放在 `…` 中，平时不占对话上方空间。运行中当前模型不变，原生确认后才更新；休眠只保存期望，不启动 Agent。关闭模型窗口不撤销已经保存的选择；撤销仍需显式操作。状态待核实／已提交配置保持只读或待核对，不重复发送原输入。输入框缩减留白和常驻操作说明，快捷键与引用提示放在悬停说明；窄窗仍保留发送、提交后台和材料状态。
- **Agent自动休眠与恢复（本轮源码，未安装）**：项目工作继续时保留调度、依赖监听和运行中的Agent；其他Agent连续安全空闲5分钟后自动卸载原生进程，显示休眠。新输入或合法后台事件按需恢复原线程和已保存模型选择，不重放旧任务；只查看状态、保存偏好或切项目不会唤醒全部角色。保存／结算、工具、原生交互、未知状态及未确认退出受到保护。休眠不结束Work、不释放它的业务名额，也不删除草稿、历史或文件。进程额度紧张时可按既有安全门提前回收。
- **空会话协议升级**：已确认接手后尚未发送任何输入的线程，只有在日志确认为本线程的纯初始化记录、历史消息和任务均能绑定到已归档线程时，才自动更新启动协议。旧历史、草稿和任务保留，不再次要求接手，也不重放输入；当前线程有消息、准入或未知归属时仍保留确认与恢复边界。有真实内容的旧会话仍须在“连接与历史”明确确认兼容接手，旧历史归档保留。
- **上下文交付（源码更新，尚未替换日常安装版）**：普通聊天只发送本次原文，Pi 负责原生历史、压缩和恢复；Nozeli 不再将旧错误或“未见消息”拼进下一轮。引用回复、明确附上的文件／选区、涂鸦问题分别冻结为有版本的材料数据，既不改写输入原文，也不变成系统指令。仅打开文件或保存批注不会发送。材料过长时明确分页或暂停，不以摘要冒充完整交付。
- **查看上下文详情**：在“会话管理”展开“上下文详情”，可查看最近原文、材料来源／版本、宿主新增内容、预算及交付阶段；打开、折叠和刷新详情不调用模型。准备内容、原生条目落盘、hook 执行和 provider 回执分别标示；没有最终请求捕获证据时不标为“模型实际看到”。连接失败仍保留原对话、草稿与诊断，发送受连接与准入限制；不会为每条技术错误自动再派后台模型诊断。失败前已完成的修改仍保留，不应直接重放整个任务。
- 对正在执行的工作发送补充时，输入进入下一回合队列，不宣称即时 steering；选区／文件讨论小窗的发送与提交任务不消费主输入草稿或其他工作草稿。

## 日常使用

- **批注与讨论**：选中文字／区域时讨论选区；无选区时右键“讨论此文件”，会话绑定整个文件而非点击位置，再次打开沿用讨论。保存本地备注或打开小窗不派工；显式发送才冻结材料。小窗可直接“提交任务”，只有确认接收才清除该次输入，提交期间新输入保留。
- **标签位置变化**：可靠定位不报警；不确定位置仅提示“位置可能偏移”，找不到原位置时仍可查看原引用、续聊或提交任务。“重新定位（可选）”不再是讨论前置条件。原材料和历史不被当前内容替换；实际修改仍检查当前版本、未保存编辑与并发变更，不能因允许讨论而绕过写入保护。
- **标签与涂鸦小窗（2026-11-06：源码统一，未安装）**：备注、文件、选区／位置、真正未定位、冻结涂鸦及审核／网页讨论接入同一窗口控制器。标题直接拖动，方向键移动、Shift 微调、Home 恢复默认；统一收起／关闭与尺寸手柄，关闭仅隐藏并保留输入。窗口位置与来源／笔迹／线程分开保存，不因标记滚出视口而消失。Linux 限定实测见[共用窗口实施](worker-review-chat-demo.md)；不是当前安装程序或全部硬件／文档格式矩阵已验收。
- **来源保持**：文件讨论绑定文件而非页内标记；真正未定位标签保留原引用并由轻量目录打开。冻结涂鸦的展示位置与笔迹独立，移动不得改笔迹、来源或自动发送；“冻结来源／版本未核验”仍如实显示。
- **任务审阅闭环**：后台任务（Work）以可阅读报告＋候选文件差异交付，在统一待办中心核对成果并明确**接受**（合入项目）或**丢弃**（不合入），也可提出修改。普通问题、澄清与内部恢复交给 Orchestrator 在后台处理，不要求用户守着回答技术问题。接受前候选不写回原文件；直接授权的前台／外部文档编辑是实时保存，不伪装成待接受候选。普通保存不产生 Git 提交，无自动 push。
- **采纳建议后继续（源码更新，未安装）**：如任务保留了当前问题报告，可从“任务概览 → 查看保留进展 → 打开报告”主动查看。接受处理方案会保存确切方案授权并推进原 Worker 的剩余步骤；拒绝时填写替代要求，按反馈继续，不等于丢弃整个任务。冷项目由该决定启动必要连接，不要求再点一次连接或重发原任务；已有任务、线程、候选和已完成操作保留。模型连接失败、人工暂停或效果待核对时明确显示尚未执行的原因，决定不丢失；原授权失效或任务版本变化不能继续套用。打开报告本身不派工，不把所有后台问题变成用户待办；这也不是最终成果的接受合入。
- **主对话直接交后台（本轮源码恢复，未安装）**：输入区同时保留“提交后台”和普通“发送”。“提交后台”把当前要求及已选材料直接交给主控，不先发送一轮前台消息；“发送”仍是前台讨论。两者共用归属、会话就绪、材料校验和草稿屏障。后台提交期间按钮显示正在提交并防止重复点击；只有宿主确认接收后才清除该次草稿／材料，失败和提交期间的新输入保留。历史只读内容不能提交。
- **成果审核与讨论（拖动问题待统一修复）**：从待办进入先阅读报告，底部保留“成果文件”“交付物Diff”“审核讨论”“采用并结束”。只有点击“审核讨论”才打开局部对话窗；进入报告、新回复、新版本都不主动弹出。关闭只隐藏同一节点，保留未发意见、选区和讨论阅读位置；采用不放在聊天输入区。审核窗纳入同一窗口控制器设计，不再另留拖动规则；当前拖动可用性待实际安装程序验收。原生报告仍有遮挡／额外裁切限制，不宣称完整无遮挡阅读。
- **原工作内容与版本**：审核窗与同一Work主对话使用相同原消息身份和正文，按原job/request及修订整理回合，同轮多段回复在一组里；原请求/主控交接和执行过程按需展开，发布报告是独立事件，不冒充AI回答。版本仍按真实发布序号显示V1/V2，人工稿另标，旧报告正文不改写。讨论仍由原Worker串行处理，不新建任务；显式发送、排队、草稿及确切版本保护保留。
- **查看保留进展（第四轮已本机安装）**：失败补充所在工作可从工作目录进入只读进展。首屏说明补充是否完成、哪些报告／文件仍可查看、当前任务能否继续，并就近提供查看稿件、复制原请求／补充和返回阅读。运行问题未处理完成时明确当前暂不能继续、不会自动恢复；打开原报告也显示当前暂停及发送／采用不可用，不把旧系统消息当作当前承诺。诊断原文、传输状态和时间收进可展开详情，原历史消息不改写。查看、复制不派工或重放，不提供无依据重试／恢复按钮；未发布内容不冒充已保留成果。
- **查看成果与交付物Diff**：底部“成果文件”展开实际文件清单，点击具体文件进入绑定报告版本的原生文档，HTML可查看网页效果及源码。底部“交付物Diff”独立列出文件，进入冻结输入→发布候选的只读比较，不含人工稿、不读取同名项目文件兜底；删除文本查看保留基线，二进制显示版本/不支持文本差异的说明，不宣称都能预览。接受前候选不写回原项目；保存人工稿后返回报告，明确采用仍经原版本确认与跨文档保存屏障。
- **HTML 前后效果**：在成果工作面切换“成果效果／前后效果／代码差异”，也可查看源码或源码＋效果。“修改前”是本次工作的冻结输入基线，并非当前磁盘文件或必然等于上一轮报告；“修改后”是当前审核候选，包含本工作面人工稿与未保存编辑并明确标识。工作面内的代码差异使用同一基线与当前稿。两侧 CSS、JS、图片均从各自审校版本取材；未冻结的依赖或缺失基线会提示不可用，不从项目文件补齐。新增文件显示无修改前版本，已删除文件显示修改前及无修改后；窄窗上下对照。切换与刷新不保存文件、不派工、不接受成果，保留编辑器、选区和撤销历史。
- **任务重启恢复**：应用重启不等于暂停、删除或完成任务。未完成 Worker／主控输入保持原任务、原队列与原线程；从未发送的原输入恢复准入，已开始的回合从原生日志续执行，不重复旧消息或已完成工具。用户明确暂停／取消持续生效；待审核保持待审核，已审核只续原收尾。原生日志缺失、权限／服务不可用、未确认工具效果或恢复期间再次崩溃的未知请求会显示恢复受阻，不能据此猜测成功或盲目重放。未发送前台草稿不会因重启发送。
- **未提交输入与收尾故障（当前源码，未安装）**：接受绑定的是任务冻结输入到确切审核候选，不要求输入此前已经 Git 提交；合入、回滚与作者记录使用同一冻结输入。原磁盘正文／权限或同文件暂存发生后续变化仍受保护。技术收尾故障由后台记录、核查和修复，普通报告只展示状态与只读详情，不增加 Git 锁处理或事务重试操作。无法确认的效果不假装成功，也不以维修名义覆盖用户编辑、扩大原授权或重放 Worker。
- **从外部粘贴文件**：先在系统文件管理器复制文件或文件夹，再在 Nozeli 左侧文件树选中目标目录，右键“粘贴”或按 Ctrl／Cmd+V；焦点在文件树空白处时粘贴到项目根目录。支持多个文件、中文和空格名称及嵌套文件夹。确认清单后复制，外部剪切也不会删除来源；同名目标不覆盖，部分失败会列出未完成项，已完成项保留。源内容／剪贴板变化时需重新复制；符号链接、特殊文件、独立项目运行元数据及未保存／待恢复冲突会拒绝。本文入口是系统“文件复制”，不是粘贴路径文字或外部拖放。
- **复制到系统文件夹（开发源码新增，旧 alpha.3 归档不含）**：在左侧文件树选择文件／文件夹，右键“复制”或按 Ctrl／Cmd+C，然后到系统文件管理器粘贴；支持多选、中文、空格和文件夹。复制发布的是已保存文件的原生路径，不是路径文字或冻结工件。未保存／待恢复冲突须先处理；运行元数据、符号链接和特殊文件拒绝导出。系统程序粘贴时按当时的磁盘内容工作、自行处理目标重名。Nozeli 内部复制仍可用；内部剪切不向外部程序授予删除源文件的移动语义。
- **分屏**：拖动标签即可并排／堆叠／多列／网格布局，同时读文档、讨论与差异；布局变化不复制文件，不丢未保存编辑。
- **紧凑输入**：内容窗格较窄时，输入框、引用／附加材料、后台提交和发送操作改为纵向排布；对话标题仅保留必要的窗口控件，其他控制在右键“更多操作”中使用。调整的是窗格宽度，不会改变或丢失草稿。
- **对话收起与更多操作（源码补修，未安装）**：标题栏向下箭头收起当前对话，点击主工作区底部对话入口恢复；不再另设“收起历史／紧凑输入”开关。历史、未发送草稿和阅读滚动位置保留，收起／恢复不发送消息。标题栏“更多”可进入会话管理；每条消息的引用、复制及适用的后台任务入口放在该消息“更多”菜单，支持键盘打开和 Escape 关闭。
- **独立窗口**：把标签脱离为真实系统窗口，放到另一块屏幕，再移回主工作区。
- **项目终端（开发源码新增，旧归档不含）**：打开项目后点击左侧“终端”，在原生工作面使用交互式 Shell，初始目录为当前项目根目录。重复点击回到同一终端；分屏、浮动、回嵌、隐藏及项目切换不重启 Shell。关闭终端内容、关闭项目或退出应用会回收所属进程。冷启动恢复布局不会重放命令或启动 Shell，请点击“启动终端”；退出后可显式重新连接。支持 ANSI、滚动历史及键盘输入；Ctrl+Shift+C/V（macOS 为 Cmd+C/V）复制／粘贴，Ctrl+C 保持中断命令。终端输出的链接不会自动打开或执行。平台能力不足时显示真实错误，不用预览模拟交互式终端；Windows/macOS 尚未取得原生生命周期验收。
- **PPTX 原件发生外部变化**：已保存的独立草稿按来源版本保留；重开时恢复旧稿会明确提示“原件已变化”，不把旧模型静默当成新源。可“查看当前磁盘版（保留草稿）”或选择恢复其他来源版本，再导出新副本。保存、快照和导出先提交编辑器内尚未同步的富文本；组合输入未结束时拒绝交接，不用等待时间代替保存确认。未解决保存冲突时，复制原文件到系统剪贴板会被拒绝；独立草稿的显式“导出新副本”不覆盖原件。
- **打开网站（新构建已支持，旧 alpha.3 归档不含）**：打开项目后，点击左侧地球图标（悬停提示“打开网站”），输入 HTTP／HTTPS 网址；网站显示在工作面，提供地址栏、后退／前进和刷新／停止，可浮动、回嵌并与本地文件切换。正常退出后恢复已访问地址；未提交地址只保存为草稿，不在恢复时自动访问。浮动／回嵌保留当前网站与表单，但退出／崩溃后不保证恢复网页表单。网站 Cookie 保存在独立本地浏览会话，不导入系统浏览器账号；所有项目共用该网站会话，并非按项目隔离账号。下载交由系统“另存为”，不自动保存或执行。网站不能调用 Nozeli／Node 接口，摄像头、麦克风、位置、通知权限当前拒绝；依赖这些权限或外部登录窗口的网站可能不可用。真实账号登录和下载对话框操作未逐站验收。
- **网页右键讨论**：网页上右键“讨论此网页”，打开可信局部讨论面板，直接讨论或提交任务。按项目与具体 URL 保存草稿和历史，不绑 DOM 位置；刷新原页继续使用，导航到另一页不改绑旧讨论，返回原页可继续。仅显式发送才冻结可见正文（最多 200000 字符），不采集表单、密码或可编辑区域；问题最多 16000 字符，超过总输入预算时明确显示正文截取数量，未发送部分不宣称模型已读取。不授予网站 Nozeli 接口或远端页面写入权限，局部提交不消费主输入草稿。

Worker 执行目录、成果冻结与合入使用流式文件处理，不再因普通文件超过 32 MiB、项目输入超过 256 MiB 或超过一万文件而拒绝执行。工作区隔离和接受后合入规则不变。文本读取与预览仍有独立预算，超出预算不等于工件丢失或任务失败；静态报告的冻结文件引用可通过“另存完整冻结工件”导出完整原件，不覆盖已有目标。磁盘不足、读取权限、文件并发变化等实际错误仍会阻止受影响操作并保留恢复现场。

所有 Agent 的原生工具以 YOLO／当前系统用户模式运行；普通文件、命令和网络默认放行。跨项目及未登记目录的文档读取、列出、搜索和显式编辑不需要授权，也不要求先打开／注册目标目录，读取不在目标创建 `.nozeli`。`.ccb`、`.github`、`.config` 等普通目录不因名称禁读；注册项目仍保护打开的草稿，外部文件编辑绑定原读取版本并拒绝并发覆盖。自动快照不收录会话元数据和依赖缓存，明确交付的安全成果即使被 Git 忽略也可冻结；Git／Nozeli内部元数据写入与凭据自动捕获不作为普通文档操作。

宿主的输入准备、工具协议、成果发布和技术收尾故障由程序记入本机 bug 日志，保留原输入、任务身份和已发生效果，沿后台维修链处理。可纠正的只读参数在原回合内处理，不要求用户重发输入；有原确切安全动作时进行有界恢复，只有实际验证后才结清故障和维修事件。普通用户界面只展示原目标、系统处理状态和必要进度，不把内部异常作为需要用户操作的业务问题；原始异常和事件保留在按需诊断中。尤其是主控尚未创建 Work 的内部失败，请求概览为只读，不要求用户理解游标、工具参数或点击执行控制维修程序。真实权限、用户并发修改及效果未知仍受保护，未验证的修复不冒充成功，也不盲目重放原业务。

**Debug 临时续行**：宿主内部故障会进入主控 Debug 定位。诊断后，如果程序能证明原调用在写入前被拒绝，并提供确切的临时恢复能力，主控会主动续行原任务，不要求你重新提交。对已经留下可靠拒绝证据的历史派工故障，恢复仍保持原请求、原 intake 与唯一 Work；不制造新故障来触发 Debug。界面显示“已临时恢复 · 原任务继续”时，不代表最终成果已完成或源码缺陷已修复；成果仍需正常审核接受。效果未知、权限未决、人工暂停／取消和身份／版本冲突不会被绕过。只有诊断而没有安全能力时显示“诊断已保存 · 等待系统修复”，不假装一直处理中；缺少现场安全证据的旧失败不自动重放。

**后台参数合同源码修复**：首次读取任务板的省略／空游标都表示首页；损坏的非空令牌仍拒绝。派工 `brief` 是可选附加说明，缺省、null 或空白时由宿主使用冻结的原请求，非空说明原样保留，不要求模型重复用户原文；其他类型会在写入前返回可纠正错误。这些正常的空参数不再触发 `INVALID_CURSOR`／`DISPATCH_BRIEF_EMPTY` 或依赖 Debug 兜底，等价重复派工仍只对应一个 Work。用户不需要填写这些内部工具参数。

用户待办只保留成果审核和真正高危的授权：管理员提权、格式化／覆盖块设备、大范围不可逆删除或明确的敏感数据外发。普通安装依赖、构建、阅读和跨目录操作不是授权理由。高危授权绑定确切命令与效果；“本任务内允许该冻结命令”也不扩展到其他管理员命令。用户拒绝或撤销继续生效，同一已完成调用只回读原回执、不重复执行。内部后台处理无法获得可靠事实时保留明确的受阻状态，不编造答案或自动丢弃成果。YOLO是信任当前用户与Agent，不是能识别任意脚本危险性的安全沙箱。

权限申请不写问题报告或成果报告。待办仅提醒“有权限需要确认”；点击会回到已有前台对话，在简洁授权卡中说明所需权限、操作范围、申请原因和具体风险，再由你明确批准或拒绝。完整命令和来源详情可展开核对；没有默认同意。打开提醒不发送消息、不清空对话草稿，Worker 的申请也不会把普通输入改绑 Worker。方案建议和最终成果仍按报告流程审阅，不能替代高危操作的确切权限授权。

**待办与顶部故障概要（2026-11-07源码已调整并通过Linux限定验收；未安装）**：顶部只保留真正需要用户处理的权威服务故障，显示单条“故障待处理 · N项／查看故障”；无故障不占位，读取失败显示待核实，不冒充零。点击后在原“服务故障与记录”窗口核对逐项范围、禁用原因并显式“故障解除，继续”；刷新、故障分页与解除批次回执也在此窗口，解除回执本身不再撑起顶部。解除仍核对原范围、版本和故障代次，不解除人工暂停，不代替审批，也不保证业务执行成功。正常排队、人工暂停和自动处理不新增故障。
消息、成果审阅和高危授权不再出现在顶部；右侧真实待办、消息“新消息”、项目红色待办角标及持久业务状态保持原规则，不通过确认提醒或标记已读来隐藏。待办数字只计算当前项目真实待处理事项；同一工作的目录行弱关联待办，不重复计数，不合并不同事项／版本。提醒更新不抢焦点、不自动切换项目。

“新事项”点绑定当前项目的确切待办 occurrence，可从更多菜单选择“标记此事项已读（仍未处理）”；只影响本次应用会话的呈现，不关闭提醒、不审核、不结算。消息的“新消息”提示单独绑定原会话和原消息身份；只有该条完整内容确实在前台可见时才清对应提示，摘要、开栏、打开报告和查看旧版本都不会清掉整条线程。缺少可靠身份的消息只保留保守提示，不编造未读数量或假装已经读完。加载与读取失败会明确写出，不把失败显示成健康的零待办。

左侧项目入口上的**红点＋数字**表示该项目尚待处理的用户事项，右侧栏收起后仍保留；超过99项显示`99+`，可访问名称保留确切数量。点击当前有待办的项目会展开“待处理”，点击其他项目仍经过原有保存与切换保护。查看和已读不会减少数字；只有权威事项不再待处理时才减少。加载显示`…`，未知显示`?`，上次有数量但当前未核实时用虚线边保留旧数，不把读取失败当成零。提醒读取不启动Agent或派发任务。

## 自动更新（开发源码新增）

设置 → 应用更新可查看当前版本、检查状态、下载进度及失败原因，并可关闭自动更新。默认从 `SeemSeam/nozeli` 的 GitHub Releases 检查较新版本（含当前 Alpha 通道的预发行）；启动后检查，之后每六小时检查。不会发送论文、批注、对话或账号凭据，但检查和下载会向 GitHub 发起网络请求。

Linux x64 的可写用户级安装与便携目录支持自动下载、校验和空闲重启；源码运行仅检查、不覆盖源码安装，Windows/macOS 自动安装尚不支持。只有系统空闲至少一分钟、无未保存编辑／输入组合／在途及排队任务、无打开的模态对话框时才保留现场并停稳重启；不会为了更新取消业务任务或强制保存冲突原件。关闭设置对话框后才能进入自动安装。
有网站工作面仍驻留时，自动更新暂停重启，避免静默丢弃网页输入；请先显式关闭网站。站点注册离开确认时，取消会保留页面。

归档经 SHA-256、精确发布标签提交、版本、平台和路径／链接边界检查后暂存；运行中的程序不被原地覆盖。新程序须完成工作面启动健康确认，否则回退旧程序，保留用户数据，不静默回滚用户内容。已回退的同一版本不会自动反复安装，可显式“立即检查更新”重试。校验和与 GitHub 标签一致性不是数字签名，也不代表第三方审计完成。已有 alpha.3 不含检测器，须先通过正常安装流程安装含此功能的新版，之后才能自动更新。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| 保存时提示外部修改冲突 | Nozeli 替换文件前会复核摘要基线并显式提示，不静默覆盖未保存编辑或把外部修改冒认给 Agent。按提示选择保留版本；不要在 Nozeli 运行时用其他工具同时改同一文件。 |
| 无法退出／退出前确认 | 有后台任务时可选择“继续留在软件”“取消任务并退出”或“强制退出”。正常取消会等待保存与子进程收尾；等待期间仍可点“强制退出”，它不等待保存或任务收尾，未保存内容可能丢失、正在执行的操作可能未完成。已持久化的文件、草稿及任务记录保留，重启不自动重放中断输入；请核对现场再显式继续。Linux 已实测自有业务子进程清理，其他平台未验收；强退后不要直接把备份视为一致快照。 |
| “关闭前未能确认保存完成”／工作区恢复（本轮已本机安装验收） | 尚在等待时可“继续等待”，程序会沿原关闭请求核验晚到结果，不重复发送业务；真正失败时可“返回工作区／返回检查”，查看具体原因。准备、保存、清理或重载等待异常时，原生恢复框另有“强制退出…”；再次确认默认取消。确认强退不再等待页面、保存或收尾，全部窗口与运行任务会终止，仅存内存的输入可能丢失，已写入记录保留。不要把强退视为保存成功或任务完成。 |
| “请先完成Nozeli独立配置初始化”／Agent 配置提示 | 在设置中完成 Nozeli 独立配置初始化（或配置 AI 源）后重试；本地阅读与历史不依赖该配置。 |
| 会话运行时不可用（`PI_*` 或旧 `OMP_RUNTIME_UNAVAILABLE`） | 安装损坏或校验失败：重新解压完整发行目录（保留可执行权限）。修复前本地阅读与历史仍可用；应用不会回退到系统 OMP/Pi。 |
| 代码补全／语言服务不可用 | JS/TS 语言服务需要系统 Node（或 `NOZELI_LSP_NODE` 指定）；没有时代码编辑与内置格式化仍可用。 |
| TeX 编译／正反向跳转不可用 | 需本机 `latexmk`＋XeLaTeX/pdfLaTeX/LuaLaTeX 或 Tectonic；TexLab、SyncTeX 为可选。缺工具不影响阅读与编辑。 |
| 隔离启动失败 | 显式启用 bubblewrap 隔离需要系统 `bwrap` 与可用命名空间；建立失败会拒绝该隔离启动，不冒充隔离成功。普通受管执行以当前用户运行，不据此宣称沙箱保护。 |
| 单条命令提权 | 仅在你逐项批准后经系统机制（如 pkexec）完成，每次由 OS 决定是否提示；应用不安装提权组件、不以 root 运行。 |

## 支持格式与已知限制

- **阅读**：PDF（大纲、搜索、缩放、文本层）；文本／Markdown／TeX／BibTeX；代码文件；图片 PNG/JPEG/WebP；DOCX；XLSX；PPTX。旧 `.doc` 仅正文文本复制导入（无图片／表格结构／样式，源文件不改动）。
- **Office 子集限制**：XLSX 图表与未知 OOXML 部分保留在原包但不显示，格式／结构编辑暂不可写；PPT 图片、转场、母版保真有限，旧 `.ppt` 不支持（PPTX 草稿独立保存，导出副本不覆盖原文件）；Word 批注与作者标记限于正文段落与表格文本。
- **PDF 批注**为页／选区级，锚定保存时版本；不承诺无损改写任意 PDF。
- 未承诺：双人文档同步编辑、任意格式截图附件回写、Office 历史二进制还原、跨设备同步。完整边界见[当前状态与能力边界](status.md)。
