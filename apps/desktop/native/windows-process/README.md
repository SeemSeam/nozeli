## Job notification member capture (2026-11-17)

Live `JobObjectBasicProcessIdList` enumeration alone can never observe a descendant that exits between two polls, so monotonic `TotalProcesses` accounting used to outrun the retained member ledger forever. Every Job now associates an I/O completion port (`JobObjectAssociateCompletionPortInformation`) before the suspended leader exists, and one dedicated collector thread blocks on `GetQueuedCompletionStatus` to pin each NEW_PROCESS incarnation immediately (OpenProcess + GetProcessTimes + IsProcessInJob, deduplicated by PID and creation time, 4096-entry budget). Message codes arrive in the transferred-byte count with a stable non-pointer completion key; only an explicit posted token ever matches the key. Live enumeration remains as a supplement. The port is drained by exactly one consumer: the owner until supervision handoff, then the original helper, which receives the port through the explicit inherited HANDLE list before its ready acknowledgement (before any resume) and keeps a bounded single-writer member-facts section so the owner lease and supervisor snapshots stay aligned. EXIT_PROCESS never grants exit authority; retained original HANDLE waits and Job accounting remain the only exit proofs, and `allProcessIncarnationsObserved` still requires `TotalProcesses` to equal the retained ledger plus leader with the announced count matching. Kernel message delivery is not guaranteed and a NEW_PROCESS can outlive its process object before dequeue: both cases keep refusing (sticky member-capture error surfaced as `memberCaptureError` with certification false), never forcing allObserved from zero active processes alone. Stopping authority is separated from completeness: `terminate` validates Job policy only, while close/cold-anchor/retirement proofs keep refusing. A deterministic fixture-churn regression (real short-lived userland descendants spawned, waited and closed by the fixture) covers plain-lease and supervised alignment; exact all-incarnation capture under adversarial exit timing remains unprovable by kernel construction and is only ever asserted through the accounting equality.
