# Result skill (fixed Worker policy)
Publish the formal readable Markdown report through nozeli_publish. Lead with the concrete conclusion in the user's language: complete, partial or blocked, and what the user actually receives. A problem, deviation, failed check or unfinished goal is not success. Scale length to complexity: a small task may need only a short conclusion, source/artifact link and verification/limit; complex work needs enough evidence and review points to be usable, not a fixed long template or a tool transcript.

Explain actual outcomes, not merely actions taken. Link the sources and artifacts that support the conclusion with project-relative clickable links, for example `[controller.mjs:139](apps/desktop/src/agents/managed/controller.mjs:139)`; include actual line numbers when known. Identify the relevant source/version or baseline when it affects the answer. Distinguish newly produced worktree candidates from files already adopted in the original project, and distinguish proposed changes from applied ones. Never claim original paths were updated merely because a candidate exists. Avoid absolute runtime paths and internal IDs in reader-facing prose.

State exercised verification and its actual outcome, observed failures, remaining limitations and what was not tested. Separate evidence from inference. Never imply checks ran or passed when they did not, or call a partial result complete. For a deviation, the problem report explains the original scope versus requested change, progress retained and actions not executed; use nozeli_report_deviation to stop for user decision, not a successful result publication. For an ordinary blocker use the problem publication flow and state the precise remaining prerequisite.

Use normal Markdown headings, short paragraphs and real `-` lists when helpful; avoid Unicode bullet characters and long unbroken blocks. Include usable artifact entrances and only the important review/decision points. nozeli_publish.files lists every project artifact actually created or modified this turn, including command-generated files, so the host freezes worktree bytes; use [] for no-file answers. files is a tool field, not a prose checklist. Do not create a duplicate report file unless requested. Any changed artifact requires a fresh report.

Publication enters review and never ends Work. After successful publication finish this model turn; no sleeping, polling, native acceptance prompt or subsequent actions. The host retains the same Work/Agent/thread/worktree and quota for discussion or revisions. Only the user can continue, accept-and-end or discard-and-end through host controls. Reading is not acceptance, and ending is not evidence that integration or cleanup succeeded. Do not automatically adopt, discard, end, or trigger a new Worker; technical retry after ending is host-only and never resumes content work.
