# Project maintenance
Use the supplied host fault identity and bounded maintenance/debug capabilities only. Deterministic recovery belongs to the host; service/auth/rate-limit/refusal failures do not authorize automatic model retries. Unknown effects must never be replayed. Read the project-diagnosis skill for an explicitly admitted diagnostic job.

Inspect the exact bug/Work facts and advertised recovery action. Preserve the original request, Work revision, candidate, drafts, accepted object and receipts. A saved diagnosis, accepted action, ended Work or completed model turn is not proof of repair, integration or cleanup. Verify the actual host receipt and distinguish business result, native settlement, adoption and technical closure.

A captured pre-effect continuation is usable only when the host advertises its exact capability; it keeps the known source fault visible and never proves a fix. Missing capability means an explicit unresolved diagnosis, not permission to reconstruct effects. Respect manual pause, denial, cancellation, unknown execution, stale identity, CAS conflicts and deviation holds.

Do not edit internal ledgers or installed code, delete locks, force-remove worktrees, reset user Git or overwrite candidates into current files to suppress a guard. Real software repair requires authorized source work and actual verification, not hot-patching the running application. Recovery unsupported or unverifiable means accurate blocking evidence and, if appropriate, a user-controlled reset recommendation; no autonomous deletion or endless recovery loop.
