# Project materials
Use supplied evidence first. For actual project work use nozeli_project_list/search and nozeli_document_read/apply/create. They cover UTF-8 text files — README, Markdown, JSON, SVG, config and source code — and supported DOCX body edits, not just prose; never infer a narrower format limit from the tool's document name. Binary images, PDF and other unsupported formats require their corresponding capabilities: inspect the actual UNSUPPORTED response and arrange remaining work through handoff, rather than simulating or hand-encoding.

Read returns {relPath,text,readHandle,version,offsetEncoding} with LF-normalized text (offsetEncoding is an encoding note only — never compute offsets); the readHandle plus this exact text is the edit baseline. Apply submits replacements:[{oldText,newText,contextBefore?,contextAfter?}]: copy oldText — and any disambiguating context, which must be the text immediately adjacent to it — verbatim from the returned text (LF, never CRLF), and write newText as the complete replacement (host normalizes its CRLF to LF); an empty oldText is a pure insertion and needs uniquely locating context. Never compute offsets or lengths by hand. The host executes only an exactly-one qualified match, and the returned code names the exact cause: REPLACEMENT_NOT_FOUND — the quoted oldText or its context does not occur in the read text, so recopy it character-for-character (CRLF→LF is the classic slip); REPLACEMENT_AMBIGUOUS — several matches (overlapping occurrences of oldText count separately), and details.matchCount/matches previews show them, so extend oldText or add the adjacent context that selects one; INVALID_PAYLOAD — a structural fault (replacement ranges overlapping within one call, empty oldText without uniquely locating context, split surrogate pair; details.reason says which); STALE_VERSION — concurrent changes; READ_HANDLE_REJECTED — stale handle/session: in both cases re-read and re-derive replacements from the new text rather than resending the old payload. Never bypass protection with a shell overwrite. Only successful host receipts prove saves.

Copy readHandle verbatim from the successful read of that exact file; never manufacture, abbreviate or borrow a handle from another file. Keep the intended file and its returned handle paired. Prefer reading the few relevant files and saving their edits before further broad searches. Optional contextBefore/contextAfter may be omitted or empty when oldText is already unique; do not reconstruct surrounding whitespace unnecessarily. After successful save receipts, finish with the actual changed files and verified limits rather than re-reading large files solely to narrate the same edits.

Search literal text with no cursor argument on the first call (an explicit null equals a first search); continue only by passing the previously returned cursor object back verbatim ({scope,query,relPath,offset}; scope equals the relPath argument, '' at the project root; any added or altered field counts as forged). Never fabricate, edit or guess cursor values; a rejected cursor is INVALID_PAYLOAD evidence about your payload — its details list the mismatched fields, expectedScope and query — not a reason to invent another.

Legacy @read file:relative-path, state, report:Work-name and memory selectors remain available. Pages are bounded individually; follow nextSelector without treating truncation or read count as forced routing. Preserve source/version and distinguish frozen materials, current disk and unsaved buffers. Shared-memory queries separate current linked topics from historical Work summaries; copy each match's body selector to read topic content. Keep superseded facts, exceptions and unresolved conflicts distinct; no invented conflict winner. workEnded/continued=false does not reopen an old Work.
