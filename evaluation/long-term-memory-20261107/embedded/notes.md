## Reproduce (parent-owned verification)

From checkout root, with the existing system Python (no install step):

```sh
python3 evaluation/long-term-memory-20261107/embedded/run.py run --output evaluation/long-term-memory-20261107/embedded/results
```

The driver reads the shared `../corpus.json` and independently authored `../oracle.json` at runtime, records their **file-byte SHA-256**, and writes `embedded/results/report.json`. Each invocation creates a fresh `results/run-*` directory with synthetic SQLite databases, backup, logical export, and crash checkpoints. It does not delete previous runs or access any application database, real report directory, credentials, model, CCB, network service, or product code. Use a different `--output` to retain separate report files. Report is written with failure details if an assertion fails; the process exits nonzero. Do not use `python -O` (assertions are acceptance checks).

Only setup capability probes were executed while authoring: Python can import stdlib `sqlite3`; SQLite reports 3.46.1, and correctly quoted `FTS5(body, tokenize="trigram")` creation succeeds, as does unicode61. An initial probe using the same name for the FTS table and column failed with `vtable constructor failed`; the corrected probe succeeded. **The full driver has not been run by this worker.** Report metrics and acceptance results are pending the parent's final execution, not claimed measurements.

## Implemented experiment paths

- A single synthetic SQLite file uses WAL + `synchronous=FULL`, append-only evidence, knowledge revisions/explicit predecessor links, events, tombstones, and lifecycle records. Database triggers reject authority UPDATE/DELETE. Head pointers and a durable extraction queue are mutable transaction state; all effects are in the same local SQLite transaction, not a second task ledger.
- Original corpus IDs are independent knowledge identities. Sharing `work` does **not** imply replacement. Current queries require exact project/instance/owner, nonrevoked source/knowledge, confirmed or verified status, and the explicit current head. Outcome accept/discard is never an approval filter. History retains the other statuses and explicit predecessor revisions. A separate two-revision report fixture tests intentional lineage and exact original source access.
- Real FTS5 unicode61 and trigram index **raw** text. CJK bigram + controlled alias index normalizes traditional Chinese, English `binary chaos`, and declared `混沌积分`/`混沌轨道积分` topic aliases. A query locator finds the longest registered canonical topic phrase inside arbitrary question wording; there is no full-question special case or semantic model. Non-topic question constraints are not understood; compound-topic questions may require explicit filters. Bigrams are AND-matched candidate tokens; normalized containment postfilters code-path/symbol collisions. Single-character CJK substring and unregistered paraphrases are unsupported.
- Oracle history/current IDs, intersected with the 10/100/1000 prefix, are compared to exact output IDs, including explicit status filters, unrelated negative controls and code suffix collisions. Per-query precision, recall, false positives and false negatives are emitted for all supported raw tokenizers; raw tokenizer misses are observations, not failed normalized-retrieval assertions. Exact CJK/alias retrieval uses the independent oracle, not a normalizer-derived expected list.
- Extraction, immutable body, FTS indexing, and deterministic extractive-summary phases commit independently, with queue phase advancement atomic with each phase's effects. Real child processes stop at durable checkpoints, the driver sends SIGKILL, then a fresh subprocess resumes the queued event from SQLite. Duplicate delivery must leave exactly one event, evidence, body, index row, and summary. This is a process-crash test, not storage-device/power-loss testing or an application Worker replay.
- Human rename/body edit is a new immutable revision with expected-head CAS. Stale edits/deletes and missing/revoked source references reject. Deletion appends a tombstone and removes current projections; previous immutable revisions remain historical evidence. Presentation rename does not break stable source identity. No filesystem edit watcher or external filename reconciliation is claimed.
- Source revoke traverses actual evidence → knowledge → summary → aggregate summary → overview summary dependencies with a recursive SQLite CTE, removes the implemented summary/FTS projections, fences reads and edits, and remains revoked after FTS rebuild/restore. Vector, graph, skill, and cache projections **are not implemented**; there are no fake invalidation passes for them.
- Owner fencing is checked inside each mutation transaction. Closing/removing/archiving and active same-path reset reject stale/unknown owners and instances; pending old-owner callbacks become cancelled. A new owner sees no old-owner knowledge. Knowledge IDs are globally unique immutable identities in this prototype; new-owner ingestion uses fresh identities, not reuse of an old global ID.
- Model-unavailable mode leaves a durable `waiting_model` event, keeps existing browse/search available, survives database reopen, and resumes from that queue when availability returns. Extraction is typed-field validation and summaries are deterministic source excerpts; **no LLM/embedding quality, inference cost, or real model outage recovery is measured**.
- Malicious SQL/shell/instruction-like source text remains parameterized data. The driver checks a shell sentinel was not created and the corpus remained present. This is a narrow data-handling demonstration, not a model/tool-injection security certification.
- HMAC-signed cursors return at most five records, bind project/instance/owner, current/history mode, status, limit and authority/queue/tokenizer version. Filter/project/version changes require resync. All pages are collected, not just the first five. Source reads use SQLite BLOB substrings, return at most 128 UTF-8 bytes without splitting codepoints, and validate the full shared source digest, revision and UTF-8 byte span via complete 31-byte-page reassembly.
- SQLite online backup, lossless logical export/import, and FTS reconstruction preserve the authority digest. The schema migration creates a versioned migration log and actually changes the bigram FTS tokenizer to `unicode61 remove_diacritics 0`, rebuilds projections, and is idempotent. This synthetic migration is not a product upgrade/rollback adapter.

## Measurements and interpretation

`report.json` records setup, enqueue, indexing, warm in-process query API and rebuild durations; wall and CPU seconds; process-lifetime `ru_maxrss` high-water marks; and SQLite/disk footprint. CPU is cumulative process time, not peak CPU percentage. Linux RSS values are KiB. Parent/self high-water and child high-water are separate; child RSS is the maximum child high-water, **not simultaneous process-tree RSS or the sum of children**. Scales run sequentially in one driver, so later self-RSS is not an isolated scale delta. Other workstation workloads can affect timing.

There are no dependency installations, so additional installed-dependency bytes are zero; the existing Python/SQLite runtime itself is not counted as zero-sized. Warm API measurements include SQL scope/status checks, Python result materialization and exact postfiltering, not just bare FTS engine execution. No cold CLI query latency is measured; subprocess startup is used only for crash/restart. Do not form a speed ratio against a competitor's cold subprocess CLI latency. All tests use synthetic small local single-writer workloads; no concurrency throughput, large-source RSS bound, disk-full, corrupted-WAL, multi-device sync, multi-process owner race stress, embedding/vector memory, model extraction, or production UX conclusion is established.

## Production-only gaps

This is runnable research, not a new application Python dependency. A production adapter must use the existing `project.sqlite` transaction/lifecycle APIs and immutable object directories, preserve original report exports, and never background-replace a user-owned old index. None of those product integrations, packaging upgrades, real directory reset races, user filesystem watchers, model callbacks, vector/graph/skill/cache adapters, or production data migrations are implemented or marked passed here. The synthetic authority digest proves only that the measured FTS rebuild did not mutate these authority tables; it is not an external object-store integrity proof.
